# Prospective clinical workspace SDK proof

This separate local harness reuses the shared staff login, session broker,
queue/detail workspace and preparation/confirmation/recovery dialog from main.
Its input admits exactly treatment and anesthesia. It supplies no production
route or deployment admission and does not replace a complete production
evidence validator with a fallback.

Each fixed scenario requires a disposable local backend owned by a separately
reviewed caller. That caller must create the genuine clinical event, establish
the expected reviewer, and admit its exact source/metadata/rows before releasing
the browser barriers. The browser logs in through the real SDK, loads one kind's
queue and server-selected detail, explicitly prepares and confirms a review,
loses the genuine execute response, accepts the actual before-unload warning,
reloads and explicitly recovers the original saved result. Read-only and Auth
barriers remain independently controlled by the backend owner.

The clinical fixture checks the declared finite clinical graph. Its dialog must
display the exact descriptive dose and route from the retained treatment row;
it never calculates a clinical dose from stock quantities. The second scenario
uses a separate fresh browser context and login. The fixed folder names and
input kind must agree. No JWT/session, policy-selection IDs or operation UUID
may be preloaded in input.

The browser driver preserves raw response evidence privately, restricts every
network origin/method/path and checks exact request ordering. Its original
120-second browser success cutoff includes normal shutdown, result persistence
and terminal output; a late result produces a separate failure marker and
refuses normal return. The owning Python caller must still enforce its original
whole-run deadline, process ownership, backend effects and successful cleanup.

The six original shared-workspace proof files in the earlier worktree are
preserved. These separately named clinical files are based on merged PR305
(`e761b21e5d1f4334af9abc90a1b46b300197ef73`). Current checks cover input and
late-persistence controls, fixture TypeScript compilation and the main suite.
The coupled authenticated clinical browser run remains prospective until its
backend caller and source/tool binding pass independent review and a real run.

All records are synthetic. Full Auth/protocol/native/production acceptance and
physical clinical activation remain false.
