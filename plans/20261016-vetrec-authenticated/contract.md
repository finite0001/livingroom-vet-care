# Clinical note templates and generation v1 contract

Independent note lane. Legacy `clinical-audio-v1` is unchanged. Audio adapters reference a persisted, same-operator audio transcript; typed sources never pretend to be recordings.

## Template

Version view: `{id, version, definition, sha256, status}`. `id` is the root UUID, version positive integer, status draft/approved/retired. Immutable `definition` is `{name, detail, fields}`: name nonempty <=120 chars; detail concise/standard/detailed; 1–48 ordered fields `{id,label,destination,instructions,required}`. Field ID matches `^[a-z][a-z0-9_]{0,47}$`, unique; label nonempty <=120 chars; destination subjective/objective/assessment/plan; instructions <=500 chars; required boolean. Field instructions total <=12000 chars. SHA256 is the server-canonical `definition::text` digest; JavaScript treats it as a pinned opaque hash. Name/labels are untrusted display data, never higher-priority instructions. Instructions are subordinate to source-fidelity rules and cannot create patient facts. No factual defaults/signatures.

## Sources, policies and reservation

`reserve_clinical_note(actor,id,request)` exact keys: pet_id,encounter_id,expected_version,policy_version,template_id,template_version,template_hash,source_kind,source_text,audio_job_id,source_note,attest_authorized. Typed has nonempty <=60000-char source_text and audio_job_id null. Audio_transcript has source_text null, audio_job_id UUID; server copies and hashes the existing same-operator persisted transcript and pins its audio policy/source identity. Source_note nonempty <=1000; attestation true. Saved patient/unsigned encounter/version, active actual operator/live session, approved exact template and current approved note policy required. Audio adapter additionally revalidates original audio policy/current source and originating session at all worker transitions. Real audio gate remains off while policy is draft.

Note policy view: `{version,status,consent_text,soap_model,reviewed_by,reviewed_at,created_at}`, soap_model `gpt-6-luna`, consent_text <=4000; approved requires reviewer/time, draft has nulls.

Read response `{job,policy,template}`. Job: id,actor_id,pet_id,encounter_id,expected_version,policy_version,template_id,template_version,template_hash,source_kind,source_text,source_sha256,audio_job_id,source_audio_policy_version,source_note,proposal_id,created_at,attempts. No session or raw request intent returned. Attempt is old audio attempt shape without stage: id,job_id,actor_id,model,state,intent,lease_until,result_hash,error_code,failure_details,provider_request_id,created_at,finished_at. Intent `{job_id,retry_of,reason,ack_cost}`. State claimed/sending/completed/failed/uncertain/superseded. Source policy/template/source/actor/expected encounter identity rechecked by database admission/dispatch/finish.

## Output and assembly

Payload `{fields,review_flags}`. Exactly one ordered field result per template entry: `{field_id,status,claims,uncertainty}`. Status supported/missing/uncertain; claims `{text,quote}` with nonempty text <=500 and literal source quote <=1000. Supported requires >=1 claim and empty uncertainty. Missing requires no claims and empty uncertainty. Uncertain requires >=1 source-backed claim and nonempty <=500-char uncertainty. No supplied headings or destinations. At most96 claims globally and24 per SOAP destination. At least one supported/source-backed claim overall. Model flags <=9, persisted <=10 (reserved deterministic terminology warning). Required missing fields derive their own review indicators, never overflow flags.

Only trusted pinned template order/labels/destinations assemble sections: populated field renders `label + ":\n" + claims.text joined "\n"`; fields in each SOAP destination join `"\n\n"`. Missing fields omitted. Each section shape `{text,quote}`, quote first literal claim excerpt or empty. All field claims and excerpts retained in provenance. Existing dictation review changes only explicitly selected unsigned SOAP destinations at exact encounter version; signing remains separate. Quotes establish source membership, not factual entailment.

## Durable provider work

New endpoint `clinical-note-process` with `CLINICAL_NOTE_PROCESSING_ENABLED` default false, same OPENAI_API_KEY. POST empty JSON, `x-note-intent` URLencoded `{job_id,attempt_id,retry_of,reason,ack_cost}`. Authenticated user calls `read_clinical_note_job` and `claim_clinical_note`; service role alone calls `dispatch_clinical_note`, `finish_clinical_note`, `fail_clinical_note`. Dispatch once, no automatic provider retry. Lost persistence acknowledgement repeats exact received result only. Explicit retry requires reason/cost acknowledgement and original state/cooldown checks. Old audio methods unchanged.

Finish result `{request_id,response_id,provider_model,contract_version,prompt_version,source_sha256,template_sha256,language_context,payload}` where contract `clinical-note-v1`, prompt_version `lrv-note-fields-v1`, source/template hashes match the job, language context is existing veterinary version/bundle SHA/request SHA receipt. Exact request hash includes model, source kind/text/hash, template identity/hash/full definition, prompt and output contract. New prompt identifier `lrv-note-fields-v1` is included in request input; source/template snapshots plus manifest retained in provenance. Provider Responses request store:false/background:false/stream:false/no tools, explicit uncached mode, 8000 output tokens and60sec timeout. Bounded source/template/output bodies, sanitized failure categories; no source/secrets in logs.

## Compatibility and checks

Never add fields to old strict audio/dictation responses. New provenance has separate RPC; existing proposal acceptance and manual import remain unchanged. Historical template/provenance reads survive retirement; new dispatch fails closed if approval changes. Tests cover exact IDs/order/source quotes/statuses/assembly, malicious template/source instructions, missing findings and negation fixtures, policy-before-provider, owned source, duplicate dispatch, uncertain outcomes, exact result persistence replay, and incomplete/refused provider output. Local real Auth/browser/SQL recovery checks remain release requirements. Stubs are not clinical model evaluations; only explicitly synthetic provider tests may use the staging key.
