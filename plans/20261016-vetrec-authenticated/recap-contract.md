# Native records recap v1 — strict contract

Status: implemented specification; processing remains inactive. Original design baseline `fd3f329a`; see [Phase 2 scope](phase-02-recapped-records.md). Keep old audio/note/SOAP contracts unchanged. The source-writer audit includes static lock-order review; actual runtime/restore and release evidence must be reported separately from the acceptance targets below.

## Common rules and authority

- All objects reject unknown keys; UUIDs canonical, hashes lowercase SHA256, versions positive integers, dates/timestamps valid ISO. Preserve original strings; reject NUL. Character limits use JavaScript UTF-16 length and ECMAScript nonblank semantics, matched server-side.
- Actual authenticated active staff + live session is required for discovery, capture, citation and review. Generation is owned by its original operator; worker transitions recheck original job/attempt sessions after waits. Reviewer is separately stamped; authority is not implicitly DVM-only. No direct client/service table grants.
- Archived/deceased patients remain eligible for authorized **historical** recap. Capture `pets.version` and lifecycle explicitly; lifecycle/identity changes stale the old manifest, but a fresh authorized historical snapshot may proceed. Never enable messaging, new care or clinical writes through this exception.
- New independent policy and `CLINICAL_RECAP_PROCESSING_ENABLED` default OFF. Provider is OpenAI using server-side `OPENAI_API_KEY`; no browser secret. Note/audio/disclosure approvals do not approve recap processing. Read/preview do not invoke a provider.

## Source discovery and immutable manifest

`Selection = {encounter_ids: UUID[0..20], include_native_problems: boolean, visit_from: date|null, visit_to: date|null}`; IDs unique and canonically ordered. Encounter dates use America/Denver calendar boundaries; require at least one eligible source overall. Dates constrain encounter selection only, not addenda or problem onset.

`SourceSet = {patient, selection, sources, membership, exclusions, budgets}`; all content resolved by server, never supplied as source text by client.
`patient = {id:UUID, version:positive_integer, name:string, species:string, breed:string|null, dob:date|null, birth_date_precision:exact|estimated|unknown, sex:unknown|female|male, neuter_status:unknown|intact|neutered, archived_at:timestamp|null, deceased_at:date|null}`. These are literal `public.pets` column names; species is native free text, not a new species enum. `id/version/name/species/birth_date_precision/sex/neuter_status` are nonnull. Omit client_id from model input while validating its saved-client linkage server-side. No contacts, address, balance or unrelated pets. Identity is header/context, not uncited model evidence.
`Source = {ref, kind, id, pet_id, version, sha256, metadata, fields}`; `ref` is deterministic `src_0001`..`src_0064` over canonical kind/ID order; `sha256` hashes the exact source projection excluding `ref`/`sha256`.

| kind | version | metadata | fields and exact citation-path whitelist |
| --- | --- | --- | --- |
| `signed_encounter` | Native `clinical_encounters.version` | `visit_at, created_by, signed_by, signed_at`; require actual signed state | `fields.subjective`, `fields.objective`, `fields.assessment`, `fields.plan` |
| `addendum` | `null`; append-only row has no invented version/signature | `encounter_id, created_by, created_at` | `fields.content` |
| `native_problem` | Native `patient_problems.version` | `created_by:UUID, created_at:timestamp, updated_by:UUID, updated_at:timestamp` (all nonnull actual columns) | `fields.title`, `fields.notes`, `fields.status`, `fields.importance`, `fields.onset_date` (quoteable only when nonnull) |

- Projection mapping: `signed_encounter` → `public.clinical_encounters` filtered status=signed; `addendum` → `public.clinical_addenda`; `native_problem` → eligible `public.patient_problems`. `fields`/`metadata` are explicit JSON grouping aliases over the named native columns. For addenda only, common Source.pet_id is derived through clinical_addenda.encounter_id → clinical_encounters.pet_id; native addenda have no pet_id/version/signed_by/signed_at/updated_by columns. Do not invent those source attributes; version is explicitly null and author/time are created_by/created_at. Problem onset_date alone is nullable; title/notes/status/importance/version and attribution above are nonnull. Problems have no signature or assigned-doctor field.
- Signed encounter metadata uses nonnull visit_at/created_by and signed_by/signed_at proven nonnull by the signed-state filter/constraint; unsigned rows have nullable signature columns and are excluded. Verify these projections against [native clinical schema](../../supabase/migrations/20260912210000_clinical_core.sql) and current [generated types](../../src/integrations/supabase/types.ts) without regenerating types.
- Encounter groups include **every** current addendum for selected parents, including those authored after the visit range. Each addendum keeps its own identity/date/author. A later addendum does not rewrite the signed encounter or establish a new examination date.
- Optional problems are the entire eligible native subset (active and resolved), bounded at 40 rows. Exclude every row linked via `ezyvet_problem_extractions`, including later locally edited rows; count/explain exclusions. Existing row status is “recorded as of capture,” not clinical confirmation or proof that a condition persists today.
- `membership = {addenda_by_encounter:[{encounter_id, source_ids}], native_problem_ids: UUID[]|null}`; lists canonical. Include membership/exclusion eligibility in the fingerprint so appends, problem creation/edits and newly outside-linked problems are detected.
- `exclusions = {outside_linked_problem_count:nonnegative_integer|null, unsupported_families:string[]}`. When include_native_problems=true, capture the actual outside-linked count; when false, set it to null in SourceSet/fingerprint material (discovery still returns the actual current number). Problem mutations or import-link count changes alone must not stale a selection that omits that group. A fixed server allowlist describes omitted families. Never silently omit an explicitly selected eligible record or incomplete addendum group.
- `budgets = {encounters, problems, source_units, source_characters, source_bytes}`; maxima 20/40/64/60000/240000. Characters are the sum of UTF-16 lengths of every nonnull string in Source.fields, including serialized onset_date/status/importance; do not count patient identity or source metadata headers toward characters. Headers and all other SourceSet fields still count toward bytes. Set budgets.source_bytes=0, serialize the complete SourceSet with PostgreSQL jsonb::text in UTF-8, assign octet_length(serialization) to source_bytes, and repeat at most8 times until unchanged. Assert the final stored source_bytes equals octet_length(final SourceSet::text); reject nonconvergence or >240000 bytes. The counter includes its own final numeric representation. Normalize every timestamp explicitly as to_char(value AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"') (six fractional digits and literal Z), independently of caller TimeZone/DateStyle; apply the same representation to captured_at. Native date-only values remain YYYY-MM-DD. America/Denver remains only the visit-date filter timezone. Refuse oversized/empty selections before reservation/provider work; no clipping. A single oversized encounter is unsupported in this increment.
- `source_fingerprint = SHA256(canonical SourceSet)`; canonical means PostgreSQL `jsonb::text` UTF-8, treated opaque by JavaScript. Preview time is not part of this fingerprint.
- `Manifest = {id, contract_version:'clinical-recap-source-v1', captured_at, source_fingerprint, source_set, sha256}`; full manifest hash covers all preceding fields, excluding its own `sha256`. This separates preview/current-source comparison from immutable capture identity/time.

Candidate `{id,version,visit_at,signed_at,addendum_count}`; keyset `next:{visit_at,id}|null`. Do not use client-shareable release discovery/publication RPCs.
- `preview_clinical_recap(actor,pet,selection)` → `{actor_id,pet_id,source_set,source_fingerprint}`. Read-only; current authority and budgets checked. This is not a persistent approval token.
- `reserve_clinical_recap(actor,job_id,request)` returns JobRead (defined below), with exact request `{pet_id,expected_pet_version,policy_version,selection,expected_source_fingerprint,source_note,attest_authorized:true,previous_job_id:UUID|null}`. Source note nonblank <=1000, server-retained only; previous job must belong to same patient. Re-resolve and compare the preview fingerprint atomically; mismatch fails without saving a partial job. Require current approved exact policy. Same UUID+same intent recovers the original reservation; changed intent/actor rejects.
- `Job = {id,actor_id,pet_id,policy_version,manifest_id,manifest_sha256,previous_job_id,source_note,created_at,output_id:UUID|null,review_version,attempts:Attempt[<=6]}`; manifest immutable, one completed output/job; review version starts1, becomes2 after one terminal review. No sessions/raw reservation intent in staff views.
- `read_clinical_recap_job(actor,job_id)` → `JobRead = {actor_id,job,manifest,policy,current,output:Output|null,review:Review|null}`. The reader may be another currently authorized staff member; provider actions still require job.actor_id to match the actual operator. Current is computed from current authorized sources using the strict Current/Reason projection below; never overwrite original snapshots. policy is the current policy at read time; job.policy_version remains the captured approval version.
- `list_clinical_recaps(actor,pet,after)` returns the strict history projection below; newest-first by created_at DESC,id DESC. `read_clinical_recap_citation(actor,job_id,source_ref)` returns the strict frozen-source envelope below; current availability is for the complete selected manifest. Current workspace navigation is separate, never a substitution for the cited snapshot.
- `cancel_clinical_recap_reservation(actor,job_id)` → `{cancelled:true,job:null}|{cancelled:false,job:Job}`. Missing job records an actor-owned immutable tombstone before input is abandoned; committed job is recovered, never deleted. Cancellation/recovery do not require a still-approved policy or active patient.

## Independent policy and durable generation

`Policy = {version,status:'draft'|'approved',consent_text<=4000,retention_text<=2000,generation_model:'gpt-6-luna',reviewed_by:UUID|null,reviewed_at:timestamp|null,created_at}`; nonblank texts, approved reviewer/time required, draft nulls. Seed draft wording for Susan; do not silently activate it.
`read_clinical_recap_policy(p_actor_id:UUID)` returns `{actor_id:UUID,policy:Policy}` for current active matched staff/live session, including before any job exists and while policy is draft.
`save_clinical_recap_policy(actor,action_id,request)` returns PolicyReceipt and is ADMIN-only with `{expected_version,status,consent_text,retention_text,attest_reviewed}` and post-lock authorization. Append a new version; require true attestation for approval. Policy actions have immutable owner/ID/request_hash bindings. `PolicyReceipt = {id,actor_id,request_hash,policy}` stores the exact resulting Policy, never substitutes the latest policy.

`recover_clinical_recap_policy(actor,action_id)` returns the actor-owned immutable PolicyReceipt or null. `cancel_clinical_recap_policy(actor,action_id)` returns `{cancelled:true,receipt:null}|{cancelled:false,receipt:PolicyReceipt}`: missing action creates an owned durable tombstone and returns true/null; already committed action returns false/the original receipt; repeated matching cancellation returns true/null. Both use IDs only and require current active matched staff/live session and action ownership, but not ADMIN or a still-approved policy. Another operator's ID is denied. Late canceled saves fail; changed request/actor reuse rejects. An owner demoted from ADMIN can recover/cancel without policy write authority; a demoted owner cannot retry an uncommitted save or create a new policy version. Browser storage retains actor/action IDs and the expected policy version only; same-tab retries reuse exact in-memory wording, while reload requires recovery or cancellation before editing. Exact receipts never relabel old jobs.

`Intent = {job_id,attempt_id,retry_of:UUID|null,reason:''|RetryReason,ack_cost:boolean}`; retry enum `previous_failure_reviewed|uncertain_outcome_duplicate_charge_authorized|expired_attempt_reviewed`. Initial retry_of=null/reason=''/ack_cost=false; UI still requires explicit send/charge authorization. Retry names latest attempt, requires fixed nonempty reason and ack_cost=true; no free clinical text in browser metadata.
`Attempt = {id,job_id,actor_id,model,state,intent,lease_until,result_hash,error_code,failure_details,provider_request_id,created_at,finished_at}`; stored intent omits attempt_id. States claimed/sending/completed/failed/uncertain/superseded. Job.attempts is newest-first by the serialized retry ancestry (leaf first), never by timestamp alone. There is one initial root and each admitted retry names the previous latest leaf; no branches, cycles or missing parents. At most6 entries; ancestry rank is primary, created_at DESC,id DESC only secondary. Equal timestamps or UUID ordering cannot make an ancestor latest. Admission/retry checks use that same authoritative leaf; clients must not reorder it. IDs bind exact owner/job/intent; initial quotas12 jobs/hour,100/day,2 live attempts/operator,6 attempts/job,90-second generation lease; no assertion that this is an aggregate quota across other features.

- Authenticated staff calls `claim_clinical_recap` and `cancel_clinical_recap_attempt` with exact arguments `{p_actor_id,p_id,p_job_id,p_retry_of,p_reason,p_ack_cost}` (the same meaning as Phase 1). Claim returns Attempt; cancel returns `{cancelled:boolean,job:Job}` with nonnull current Job and exact owner/intent matching. Read JobRead separately after cancellation; this Job summary is not a complete source/currentness envelope. Service-only `dispatch_clinical_recap(attempt_id)`, `finish_clinical_recap(attempt_id,result)`, `fail_clinical_recap(attempt_id,uncertain,code,details)`; dispatch returns true once only. Finish returns only `{job_id:UUID,attempt_id:UUID,retained:boolean,outcome:completed|policy_changed|forbidden}`; it never returns clinical snapshots. A revoked policy/session must commit the sanitized attempt outcome and return retained=false rather than raise an exception that would roll that change back. Exact result persistence replay returns the same receipt; after retained=true the handler obtains JobRead through a new authenticated staff read. A failed fresh read exposes no clinical result and never repeats the provider call. Failure details whitelist bounded http_status/provider_code/request_id/retry_after_seconds, never raw source/provider error text. Tombstones block late claims before stale-policy checks; claimed cancellation prevents dispatch; sending/completed are retained and recovered.
- `clinical-recap-process` POST `{}` with URLencoded `x-recap-intent`; authenticate using user JWT, read owned pinned job, then admit and dispatch. Revalidate source/policy/session before dispatch; no tools, external fetch or record discovery by the model. Request store:false/background:false/stream:false, explicit uncached mode, <=8000 output tokens,60-second timeout; request hash includes complete manifest, policy/model, prompt, vocabulary and output contract.
- No provider retry inside handler. Known errors versus uncertain/billed outcomes retain sanitized metadata; honor cooldown. Received output persistence may repeat the **same** result, never the provider call. After all finish waits, retaining any received raw output/quotes requires the exact job policy still be the current approved policy and both original job and attempt actors/sessions remain valid. Source-only changes under those conditions may retain a visibly stale output. Changed/revoked policy or invalid job/attempt session produces sanitized outcome metadata only: no raw output, claims, quotes or raw provider error text is stored/exposed. Free-text retention_text is disclosure, not executable permission. Do not resend the provider request; preserve the existing immutable input manifest and classify an unpersisted received result explicitly.

## Output and internal review

`Payload = {claims:Claim[1..48],review_flags:string[<=10]}`; model max9 flags, one slot reserved for deterministic vocabulary warning. Claim IDs unique sequential `claim_001`..`claim_048`.
`Claim = {claim_id,category,temporal_status,text,uncertainty,citations:Citation[1..4]}`; text nonblank<=500, uncertainty<=500; uncertain status requires explanation, other statuses empty explanation. Category history/problem_status/medication_vaccine_mention/conflict. Temporal status historical/recorded_status_as_of_capture/uncertain; recorded_status requires a native-problem status citation, never a historical SOAP sentence promoted into current diagnosis.
`Citation = {source_ref,field_path,quote}`; quote nonblank<=1000, literal substring of the exact cited nonnull field. Validate ref/path whitelist and membership; raw source IDs, versions/hashes and dates come from the manifest. No generated links/dates/authorities. Every factual claim needs evidence; flags/coverage labels cannot establish undocumented absence of disease/treatment.
`Result = {request_id<=200,response_id<=200,provider_model<=200,contract_version:'clinical-recap-v1',prompt_version:'lrv-recap-claims-v1',manifest_sha256,language_context:{version,bundle_sha256,request_sha256},payload}`; strict complete Responses output only. Retain exact result/hash and proposal payload hash; source text/IDs cannot be replaced by provider output.
`Output = {id:attempt_id,job_id,manifest_sha256,payload,payload_sha256,provider_manifest,created_at}`; immutable. Current source match permits review. A source-only change during processing retains a visibly stale output only under the finish authority rule above, blocks acceptance, and never automatically regenerates or changes sources. Policy/session change permits sanitized outcome metadata only, with no raw output persistence.

- `save_clinical_recap_review(actor,action_id,request)` exact request `{job_id,output_id,expected_output_hash,expected_review_version,manifest_sha256,decision:'accepted'|'rejected',accepted_claims:[{claim_id,text}],review_note<=2000,attest_reviewed:true}`. Accept1..48 unique original claim IDs with nonblank text<=500, preserve original citation/category/temporal metadata; text maps only to reviewed_text in the retained item. Retain accepted items in original output claim order, independent of request/checkbox order. Reviewer edits remain distinct from model wording. Reject requires empty accepted_claims and nonblank reason. No invented new claim/source through this route.
- Acceptance atomically checks current sources, current exact approved policy, patient linkage, reviewer/session and expected version/output/hash; one terminal review/output. Conflict preserves local edits and original output. Rejection/owned receipt recovery may close stale work without commissioning processing. Reviewed recap is immutable, attributed separately to reviewer; later correction uses a new linked job/review.
`ReviewedClaim = {claim_id,category,temporal_status,uncertainty,citations:Citation[1..4],proposed_text:nonblank<=500,reviewed_text:nonblank<=500}`. Every field except reviewed_text is copied exactly from the original validated Claim; proposed_text is its original text. No new metadata or citation is accepted from the browser.
`Review = {id:action_id,job_id,output_id,reviewer_id,decision,accepted_claims:ReviewedClaim[0..48],review_note,manifest_sha256,output_sha256,version:2,created_at}`. Null before review; rejection has accepted_claims:[], acceptance has1..48. expected_output_hash and Review.output_sha256 both mean exact Output.payload_sha256; manifest_sha256 means exact Manifest.sha256. `Receipt = {id,actor_id,job_id,request_hash,review}`. Save review returns Receipt; request_hash is the opaque server-canonical exact-request hash.

- `recover_clinical_recap_review(actor,action_id,job_id)` returns the bound immutable Receipt or null; `cancel_clinical_recap_review(actor,action_id,job_id)` returns `{cancelled:true,receipt:null}|{cancelled:false,receipt:Receipt}` and records an owned action tombstone if absent. Review action recovery uses actor/action_id/job_id and returns the bound immutable receipt (including request hash); retry in the same tab reuses exact in-memory request. After reload, recover receipt or durably cancel the action ID before editing; never persist source, edits or review note in browser storage. Late canceled reviews reject. Configuration/review cancellation cannot cancel an already committed outcome.
- No `clinical_dictation_proposals` insertion, `save_clinical_dictation_action`, encounter/problem mutation, signature, outbox, certificate, export or public link. A future reviewed_recap note adapter requires separate explicit selection/provenance/policy contract; no automatic clinical context insertion.

## Exact transport projections and safe refusals

All keys below are required; nullable fields are explicit and unknown keys reject. Abstract actor/action/job arguments above map to p_actor_id/p_id/p_job_id where named below; source discovery retains its separately specified visit cursor. Do not persist returned content-bearing envelopes in browser recovery storage.

### Job and reservation envelope

`reserve_clinical_recap(p_actor_id:UUID,p_id:UUID,p_request:ReserveRequest)` and `read_clinical_recap_job(p_actor_id:UUID,p_id:UUID)` both return JobRead. New reservation guarantees job.id=p_id, job.actor_id=actor_id=p_actor_id, empty attempts, output/review null, review_version1 and Current current. Same-intent recovery may return the later output/review/currentness of that original immutable capture. It never creates another job or relabels its policy version.

Validate job/actor/patient identity; manifest ID/hash agreement across job/envelope/output/review; captured patient version, canonical selection and requested source fingerprint; previous job ID and same-tab source note against the exact in-memory request. JavaScript validates opaque hash shape and bindings, not PostgreSQL hash reproduction. On reload, match retained IDs/versions/hashes and actual session authority; never reconstruct discarded source notes. Historical recovery with changed sources returns the original frozen manifest plus stale/unavailable status when authorized, not replacement content.

Exact policy transport: `save_clinical_recap_policy(p_actor_id,p_id,p_request)` returns PolicyReceipt; `recover_clinical_recap_policy(p_actor_id,p_id)` returns PolicyReceipt|null; `cancel_clinical_recap_policy(p_actor_id,p_id)` returns the cancellation union already specified. ### Citation and currentness

`Reason = 'patient_changed'|'encounters_changed'|'addenda_changed'|'problems_changed'|'problem_eligibility_changed'|'source_unavailable'` in that canonical order. `Current = {source_status:'current'|'stale'|'unavailable',reasons:Reason[0..6]}`. Reasons are unique/canonical. Current requires []; stale requires at least one changed reason and excludes source_unavailable; unavailable requires source_unavailable and may include changed reasons. Policy state never masquerades as a source reason. Problems/eligibility reasons cannot result solely from an omitted optional problem group.

`read_clinical_recap_citation(p_actor_id:UUID,p_job_id:UUID,p_source_ref:string)` returns `{actor_id:UUID,pet_id:UUID,job_id:UUID,manifest_id:UUID,manifest_sha256:SHA256,source_ref:string,source:Source,current:Current}`. source_ref must be an actual src_0001..src_0064 member, not merely pattern-valid. Source.ref matches the request; Source.pet_id matches Job.pet_id; every frozen ID/version/hash/field remains exact. Current describes the complete selected manifest, not which individual source changed. Current staff authority is required anew; failure returns no frozen content. Authorized retained unavailable sources may remain readable as history under the saved-patient/retention rules, never as current evidence.

No HTML, external URL, generated author/date or current-row substitution is returned. A separate local current-clinical-workspace link may navigate to the containing patient Medical/SOAP section; exact-row focus is outside v1. Addendum parent encounter_id remains evidence, not a promise of row focus.

### Refusals

`Refusal = {code:RefusalCode,source_reasons:Reason[0..6],budget_violations:BudgetViolation[0..5],retry_after_seconds:integer(0..86400)|null}`. No source text, names, IDs, quotes or raw database/provider error text belongs in this projection. Authorization precedes any source-derived budget/count disclosure.

`RefusalCode = 'invalid_request'|'authentication_required'|'forbidden'|'not_found'|'operation_unavailable'|'policy_unapproved'|'policy_changed'|'source_changed'|'source_unavailable'|'empty_selection'|'budget_exceeded'|'identity_conflict'|'intent_conflict'|'action_cancelled'|'review_conflict'|'attempt_active'|'retry_not_allowed'|'processing_disabled'|'rate_limited'|'provider_rejected'|'provider_unavailable'|'provider_uncertain'|'invalid_provider_output'`.

`BudgetViolation = {dimension:'encounters'|'problems'|'source_units'|'source_characters'|'source_bytes',observed:nonnegative_integer,limit:positive_integer}`. Limits are exactly20/40/64/60000/240000 respectively. Violations are unique in that order and each has observed>limit. budget_exceeded requires1..5 violations; other codes require []. source_changed excludes source_unavailable. A preview-fingerprint mismatch during reservation returns source_reasons:[] because the prior opaque hash cannot identify a changed family; manifest-bound checks return the actual changed Reasons; source_unavailable requires that Reason. Other codes use source_reasons:[]. retry_after_seconds is a sanitized numeric delay only, otherwise null. Structurally invalid/noncanonical selections use invalid_request; authorized well-formed selections exceeding resolved source budgets use budget_exceeded. Neither creates partial captures.

For recognized PostgREST SQL refusals, details is exactly serialized Refusal JSON, parsed strictly by the API. Never render ordinary message/hint or unknown details. SQL status mapping: PT401 authentication_required; PT403 forbidden/policy_unapproved; PT404 not_found; PT422 invalid_request/empty_selection/budget_exceeded; PT409 policy_changed/source_changed/source_unavailable/identity_conflict/intent_conflict/action_cancelled/review_conflict/attempt_active/retry_not_allowed; PT429 rate_limited; PT503 operation_unavailable. Earlier database permission failures without a recognized envelope still receive safe normalization.

Edge returns `{error:Refusal}`: matching401/403/404/409/422/429 for those categories;503 for operation_unavailable/processing_disabled/provider_unavailable;502 for provider_rejected/invalid_provider_output;504 for provider_uncertain. Processing gate OFF always uses processing_disabled/503. Unknown/nonconforming failures normalize to operation_unavailable with empty arrays/null delay; never infer diagnosis, budget dimensions or retry timing from raw text. Existing immutable Attempt.failure_details remains a separate bounded provider-metadata whitelist and is never rendered as a raw provider response.

## Source synchronization and proof boundary

Membership checks must serialize appends and updates, not only compare signed encounter versions. DB audit found native problem writes lock pets and addendum inserts lock their parent encounter **before** an AFTER-write source epoch. Acquiring native-source FK/row locks after that epoch can deadlock, including implicit FK KEY SHARE checks.
Selected structural rule: **no native-source FKs**, including job/manifest/epoch pet_id and source encounter/addendum/problem IDs. Retain immutable canonical UUID/version/hash snapshots; RPC validates saved pet/client existence, exact patient linkage, eligibility and current staff authority. Native pets are undeletable through the normal workflow; retained snapshots do not depend on source-row FK retention. Under the epoch lock, read all identity/membership/content in one fresh plain SELECT without acquiring canonical source row/FK locks. New private-table dependencies need consistent job/epoch lock order. Initialize/backfill an epoch for every saved patient, create it on pet INSERT and fail closed if missing. The migration explicitly wraps all changes in BEGIN/COMMIT and locks pets in SHARE ROW EXCLUSIVE mode before its backfill snapshot, retaining that lock until the initializer trigger is installed and commits. Mutation families are pets, clinical_encounters, clinical_addenda, patient_problems and ezyvet_problem_extractions link eligibility. Capture/guard RPCs are VOLATILE/default under READ COMMITTED; saved-manifest-only projection may be STABLE. ## Private lock map

This is the implemented ordering. The [local/staging receipt](../../docs/launch-evidence/2026-10-16-clinical-record-recaps.md) names observed cases; the acceptance matrix remains a target inventory rather than a blanket proof of all possible interleavings. Every mutating or current-source-checking RPC uses READ COMMITTED and VOLATILE/default. All lock-bearing paths follow this order, skipping unnecessary levels and never acquiring an earlier level afterward:

1. Practice policy mutex: `pg_advisory_xact_lock(hashtextextended('clinical-recap-policy',0))`. Policy save/cancel, source preview/reservation, work transitions, currentness/citation checks and review/cancel paths acquire it first. Acquiring this mutex never itself requires policy approval; cancellations/rejections/recovery remain usable when processing is disabled. No external provider request runs while any database transaction/mutex is held.
2. Optional operator quota mutex: `pg_advisory_xact_lock(hashtextextended('clinical-recap-actor:'||actor_uuid::text,0))`, required for reservation/claim admission and used consistently by their staff cancellation counterparts. Workers never acquire an operator mutex after locking a job.
3. At most one durable action mutex per RPC: `pg_advisory_xact_lock(hashtextextended('clinical-recap-action:'||family||':'||action_uuid::text,0))`, family policy/reservation/attempt/review. Policy IDs, reservation job IDs, attempt IDs and review action IDs bind their corresponding immutable receipt/tombstone namespaces. Worker dispatch/finish/fail may skip this mutex; the job/attempt locks below serialize them with cancellation.
4. Existing private job row `FOR UPDATE` for mutations, `FOR SHARE` for a currentness/citation read; then existing private attempt row `FOR UPDATE` for worker/cancel transitions. Reserve uses the reservation action mutex to serialize a not-yet-existing job. Output/manifest/source rows are immutable plain reads; review competition serializes on the job's review_version, not another late lock. Do not acquire another job, policy or action lock after this level. Validate previous_job_id with a plain same-patient/authority read and retain its UUID without a cross-job FK, avoiding an implicit second-job lock during later insertion.
5. At most one patient source mutex: `pg_advisory_xact_lock(hashtextextended('clinical-recap-source:'||pet_uuid::text,0))`; then that patient's preexisting private epoch row `FOR UPDATE`. Preview has no job level. A currentness read still takes this epoch order. Source capture is ONE fresh plain native SELECT after these waits, followed by post-wait session/role checks and bounded private-only writes. There are no native-source FKs/row locks in this phase; actor audit FK locks, if used, must already be satisfied outside it.

Operation routes: policy save/cancel =1→3(policy); preview=1→5; reservation=1→2→3(reservation)→4(if present)→5; claim=1→2→3(attempt)→4→5; staff attempt cancel=1→2→3(attempt)→4 with no source/policy eligibility requirement; worker dispatch/finish=1→4→5; sanitized worker failure=1→4 without source capture; acceptance=1→3(review)→4→5; rejection/review cancellation=1→3(review)→4 without current-source/policy eligibility; reservation cancellation=1→2→3(reservation)→4(if present). Exact saved-receipt/tombstone recovery is an authorized immutable plain read and never attempts a policy mutation or provider dispatch. Current job/citation read=1→4(shared job)→5. Discovery and list summaries are authorized plain reads without a claim of atomically current source status; opening a job computes currentness through the locking route.

Source AFTER-mutation triggers acquire only5 (patient source mutex, then private epoch row) after native writers' existing locks. They never acquire policy, operator, action, job, attempt or recap review locks. Pet INSERT initializes its private epoch before visibility; migration backfill/install is atomic. Other mutations require an existing epoch and fail closed if missing. An extraction derives the actual affected pet from its problem; addendum derives it from its encounter. Sources/membership are never read before a wait and reused afterward.

Hash collisions may conservatively serialize unrelated keys but do not authorize cross-operator work; exact stored identities remain mandatory. Current public source writers operate on one existing patient. Future/arbitrary multi-patient transactions and a source writer that begins acquiring recap private/policy locks need a separate ordering proof. Observed blocker/wait tests must establish this map before claiming runtime correctness.

Acceptance evidence: wrong patient/operator/session, archived/deceased history, complete addendum groups, outside-linked exclusion, stale/mixed chronology, exact citations, hostile source instructions, bounded refusal, source-write lock races, cancel/dispatch/review races, lost acknowledgements, populated restore, zero canonical clinical/outbox writes, desktop/390px and separate bounded synthetic-provider fidelity evaluation. No PDF/OCR/URL ingestion or additional native adapters are included.
