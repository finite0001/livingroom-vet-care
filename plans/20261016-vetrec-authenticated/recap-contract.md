# Native records recap v1 — proposed strict contract

Status: design, not implementation or activation. Baseline `fd3f329a`; see [Phase 2 scope](phase-02-recapped-records.md). Keep old audio/note/SOAP contracts unchanged. The source-writer audit is complete as a static design review; implementation remains provisional until the concurrent-write/race checks below pass.

## Common rules and authority

- All objects reject unknown keys; UUIDs canonical, hashes lowercase SHA256, versions positive integers, dates/timestamps valid ISO. Preserve original strings; reject NUL. Character limits use JavaScript UTF-16 length and ECMAScript nonblank semantics, matched server-side.
- Actual authenticated active staff + live session is required for discovery, capture, citation and review. Generation is owned by its original operator; worker transitions recheck original job/attempt sessions after waits. Reviewer is separately stamped; authority is not implicitly DVM-only. No direct client/service table grants.
- Archived/deceased patients remain eligible for authorized **historical** recap. Capture `pets.version` and lifecycle explicitly; lifecycle/identity changes stale the old manifest, but a fresh authorized historical snapshot may proceed. Never enable messaging, new care or clinical writes through this exception.
- New independent policy and `CLINICAL_RECAP_PROCESSING_ENABLED` default OFF. Provider is OpenAI using server-side `OPENAI_API_KEY`; no browser secret. Note/audio/disclosure approvals do not approve recap processing. Read/preview do not invoke a provider.

## Source discovery and immutable manifest

`Selection = {encounter_ids: UUID[0..20], include_native_problems: boolean, visit_from: date|null, visit_to: date|null}`; IDs unique and canonically ordered. Encounter dates use America/Denver calendar boundaries; require at least one eligible source overall. Dates constrain encounter selection only, not addenda or problem onset.

`SourceSet = {patient, selection, sources, membership, exclusions, budgets}`; all content resolved by server, never supplied as source text by client.
`patient = {id:UUID, version:positive_integer, name:string, species:string, breed:string|null, dob:date|null, birth_date_precision:exact|estimated|unknown, sex:unknown|female|male, neuter_status:unknown|intact|neutered, archived_at:timestamp|null, deceased_at:date|null}`. These are literal `public.pets` column names; species is native free text, not a new species enum. `id/version/name/species/birth_date_precision/sex/neuter_status` are nonnull. Omit client_id from model input while validating its saved-client linkage server-side. No contacts, address, balance or unrelated pets. Identity is header/context, not uncited model evidence.
`Source = {ref, kind, id, pet_id, version, sha256, metadata, fields}`; `ref` is deterministic `src_0001`..`src_0064` over canonical kind/ID order; `sha256` hashes the exact source projection excluding `ref`/`sha256`.

| kind | version | metadata | fields and exact citation-path whitelist |
| --- | --- | --- | --- |
| `signed_encounter` | Native `clinical_encounters.version` | `visit_at, created_by, signed_by, signed_at`; require actual signed state | `fields.subjective`, `fields.objective`, `fields.assessment`, `fields.plan` |
| `addendum` | `null`; append-only row has no invented version/signature | `encounter_id, created_by, created_at` | `fields.content` |
| `native_problem` | Native `patient_problems.version` | `created_by:UUID, created_at:timestamp, updated_by:UUID, updated_at:timestamp` (all nonnull actual columns) | `fields.title`, `fields.notes`, `fields.status`, `fields.importance`, `fields.onset_date` (quoteable only when nonnull) |

- Projection mapping: `signed_encounter` → `public.clinical_encounters` filtered status=signed; `addendum` → `public.clinical_addenda`; `native_problem` → eligible `public.patient_problems`. `fields`/`metadata` are explicit JSON grouping aliases over the named native columns. For addenda only, common Source.pet_id is derived through clinical_addenda.encounter_id → clinical_encounters.pet_id; native addenda have no pet_id/version/signed_by/signed_at/updated_by columns. Do not invent those source attributes; version is explicitly null and author/time are created_by/created_at. Problem onset_date alone is nullable; title/notes/status/importance/version and attribution above are nonnull. Problems have no signature or assigned-doctor field.
- Signed encounter metadata uses nonnull visit_at/created_by and signed_by/signed_at proven nonnull by the signed-state filter/constraint; unsigned rows have nullable signature columns and are excluded. Verify these projections against [native clinical schema](../../supabase/migrations/20260912210000_clinical_core.sql) and current [generated types](../../src/integrations/supabase/types.ts) without regenerating types.
- Encounter groups include **every** current addendum for selected parents, including those authored after the visit range. Each addendum keeps its own identity/date/author. A later addendum does not rewrite the signed encounter or establish a new examination date.
- Optional problems are the entire eligible native subset (active and resolved), bounded at 40 rows. Exclude every row linked via `ezyvet_problem_extractions`, including later locally edited rows; count/explain exclusions. Existing row status is “recorded as of capture,” not clinical confirmation or proof that a condition persists today.
- `membership = {addenda_by_encounter:[{encounter_id, source_ids}], native_problem_ids: UUID[]|null}`; lists canonical. Include membership/exclusion eligibility in the fingerprint so appends, problem creation/edits and newly outside-linked problems are detected.
- `exclusions = {outside_linked_problem_count, unsupported_families: string[]}`; a fixed server allowlist describes omitted families. Never silently omit an explicitly selected eligible record or incomplete addendum group.
- `budgets = {encounters, problems, source_units, source_characters, source_bytes}`; maxima 20/40/64/60000/240000. Characters count clinical string fields; bytes bound canonical SourceSet UTF-8. Refuse oversized/empty selections before reservation/provider work; no clipping. A single oversized encounter is unsupported in this increment.
- `source_fingerprint = SHA256(canonical SourceSet)`; canonical means PostgreSQL `jsonb::text` UTF-8, treated opaque by JavaScript. Preview time is not part of this fingerprint.
- `Manifest = {id, contract_version:'clinical-recap-source-v1', captured_at, source_fingerprint, source_set, sha256}`; full manifest hash covers all preceding fields, excluding its own `sha256`. This separates preview/current-source comparison from immutable capture identity/time.

## Discovery, reservation and reads

- `list_clinical_recap_sources(actor,pet,visit_from,visit_to,after)` → `{actor_id,pet_id,encounters:[candidate<=20],native_problem_count,outside_linked_problem_count,has_more,next}`. Candidate `{id,version,visit_at,signed_at,addendum_count}`; keyset `next:{visit_at,id}|null`. Do not use client-shareable release discovery/publication RPCs.
- `preview_clinical_recap(actor,pet,selection)` → `{actor_id,pet_id,source_set,source_fingerprint}`. Read-only; current authority and budgets checked. This is not a persistent approval token.
- `reserve_clinical_recap(actor,job_id,request)` exact request `{pet_id,expected_pet_version,policy_version,selection,expected_source_fingerprint,source_note,attest_authorized:true,previous_job_id:UUID|null}`. Source note nonblank <=1000, server-retained only; previous job must belong to same patient. Re-resolve and compare the preview fingerprint atomically; mismatch fails without saving a partial job. Require current approved exact policy. Same UUID+same intent recovers the original reservation; changed intent/actor rejects.
- `Job = {id,actor_id,pet_id,policy_version,manifest_id,manifest_sha256,previous_job_id,source_note,created_at,output_id:UUID|null,review_version,attempts:Attempt[<=6]}`; manifest immutable, one completed output/job; review version starts1, becomes2 after one terminal review. No sessions/raw reservation intent in staff views.
- `read_clinical_recap_job(actor,job_id)` → `{actor_id,job,manifest,policy,current,output,review}`. The reader may be another currently authorized staff member; provider actions still require job.actor_id to match the actual operator. `current:{source_status:'current'|'stale'|'unavailable',reasons:Reason[]}` computed from current authorized sources; never overwrite original snapshots. Reasons are fixed nonclinical codes, including patient_changed/addenda_changed/problems_changed/source_unavailable.
- `list_clinical_recaps(actor,pet,after)` → `{actor_id,pet_id,items:[job-summary<=20],has_more,next}`; newest-first, keyset `{created_at,id}`. `read_clinical_recap_citation(actor,job_id,source_ref)` returns the exact frozen source plus current availability/stale state; link to current row separately, never substitute it for the cited historical snapshot.
- `cancel_clinical_recap_reservation(actor,job_id)` → `{cancelled,job:Job|null}`. Missing job records an actor-owned immutable tombstone before input is abandoned; committed job is recovered, never deleted. Cancellation/recovery do not require a still-approved policy or active patient.

## Independent policy and durable generation

`Policy = {version,status:'draft'|'approved',consent_text<=4000,retention_text<=2000,generation_model:'gpt-6-luna',reviewed_by:UUID|null,reviewed_at:timestamp|null,created_at}`; nonblank texts, approved reviewer/time required, draft nulls. Seed draft wording for Susan; do not silently activate it.
`save_clinical_recap_policy(actor,action_id,request)` is ADMIN-only with `{expected_version,status,consent_text,retention_text,attest_reviewed}` and post-lock authorization. Append a new version; require true attestation for approval. Owner recovery/durable cancellation of an action must remain available to current staff after ADMIN demotion, without permitting policy changes; exact receipts never relabel old jobs.

`Intent = {job_id,attempt_id,retry_of:UUID|null,reason:''|RetryReason,ack_cost:boolean}`; retry enum `previous_failure_reviewed|uncertain_outcome_duplicate_charge_authorized|expired_attempt_reviewed`. Initial retry_of=null/reason=''/**ack_cost=false**; UI still requires explicit send/charge authorization. Retry names latest attempt, requires fixed nonempty reason and ack_cost=true; no free clinical text in browser metadata.
`Attempt = {id,job_id,actor_id,model,state,intent,lease_until,result_hash,error_code,failure_details,provider_request_id,created_at,finished_at}`; stored intent omits attempt_id. States claimed/sending/completed/failed/uncertain/superseded. IDs bind exact owner/job/intent; initial quotas12 jobs/hour,100/day,2 live attempts/operator,6 attempts/job,90-second generation lease; no assertion that this is an aggregate quota across other features.

- Authenticated staff calls `claim_clinical_recap` and `cancel_clinical_recap_attempt` with the exact Phase 1 claim/cancel argument shape (actor,id,job_id,retry_of,reason,ack_cost). Service-only `dispatch_clinical_recap(attempt_id)`, `finish_clinical_recap(attempt_id,result)`, `fail_clinical_recap(attempt_id,uncertain,code,details)`; dispatch returns true once only. Failure details whitelist bounded http_status/provider_code/request_id/retry_after_seconds, never raw source/provider error text. Tombstones block late claims before stale-policy checks; claimed cancellation prevents dispatch; sending/completed are retained and recovered.
- `clinical-recap-process` POST `{}` with URLencoded `x-recap-intent`; authenticate using user JWT, read owned pinned job, then admit and dispatch. Revalidate source/policy/session before dispatch; no tools, external fetch or record discovery by the model. Request store:false/background:false/stream:false, explicit uncached mode, <=8000 output tokens,60-second timeout; request hash includes complete manifest, policy/model, prompt, vocabulary and output contract.
- No provider retry inside handler. Known errors versus uncertain/billed outcomes retain sanitized metadata; honor cooldown. Received output persistence may repeat the **same** result, never the provider call. Policy/session revocation prevents new acceptance; preserve received stale output only when current authority/retention permit, otherwise retain sanitized outcome without exposing output.

## Output and internal review

`Payload = {claims:Claim[1..48],review_flags:string[<=10]}`; model max9 flags, one slot reserved for deterministic vocabulary warning. Claim IDs unique sequential `claim_001`..`claim_048`.
`Claim = {claim_id,category,temporal_status,text,uncertainty,citations:Citation[1..4]}`; text nonblank<=500, uncertainty<=500; uncertain status requires explanation, other statuses empty explanation. Category history/problem_status/medication_vaccine_mention/conflict. Temporal status historical/recorded_status_as_of_capture/uncertain; recorded_status requires a native-problem status citation, never a historical SOAP sentence promoted into current diagnosis.
`Citation = {source_ref,field_path,quote}`; quote nonblank<=1000, literal substring of the exact cited nonnull field. Validate ref/path whitelist and membership; raw source IDs, versions/hashes and dates come from the manifest. No generated links/dates/authorities. Every factual claim needs evidence; flags/coverage labels cannot establish undocumented absence of disease/treatment.
`Result = {request_id<=200,response_id<=200,provider_model<=200,contract_version:'clinical-recap-v1',prompt_version:'lrv-recap-claims-v1',manifest_sha256,language_context:{version,bundle_sha256,request_sha256},payload}`; strict complete Responses output only. Retain exact result/hash and proposal payload hash; source text/IDs cannot be replaced by provider output.
`Output = {id:attempt_id,job_id,manifest_sha256,payload,payload_sha256,provider_manifest,created_at}`; immutable. Current source match permits review; source change during processing retains a visibly stale output when allowed, blocks acceptance, and never automatically regenerates or changes sources.

- `save_clinical_recap_review(actor,action_id,request)` exact request `{job_id,output_id,expected_output_hash,expected_review_version,manifest_sha256,decision:'accepted'|'rejected',accepted_claims:[{claim_id,text}],review_note<=2000,attest_reviewed:true}`. Accept >=1 unique original claim, preserve original citation/category/temporal metadata; reviewer edits remain distinct from model wording. Reject requires empty accepted_claims and nonblank reason. No invented new claim/source through this route.
- Acceptance atomically checks current sources, current exact approved policy, patient linkage, reviewer/session and expected version/output/hash; one terminal review/output. Conflict preserves local edits and original output. Rejection/owned receipt recovery may close stale work without commissioning processing. Reviewed recap is immutable, attributed separately to reviewer; later correction uses a new linked job/review.
`Review = {id:action_id,job_id,output_id,reviewer_id,decision,accepted_claims,review_note,manifest_sha256,output_sha256,version:2,created_at}`. Null before review. Accepted claims retain original IDs/citations plus proposed and reviewed wording. `Receipt = {id,actor_id,job_id,request_hash,review}`.

- `recover_clinical_recap_review(actor,action_id,job_id)` returns the bound immutable Receipt or null; `cancel_clinical_recap_review(actor,action_id,job_id)` returns `{cancelled,receipt:Receipt|null}` and records an owned action tombstone if absent. Review action recovery uses actor/action_id/job_id and returns the bound immutable receipt (including request hash); retry in the same tab reuses exact in-memory request. After reload, recover receipt or durably cancel the action ID before editing; never persist source, edits or review note in browser storage. Late canceled reviews reject. Configuration/review cancellation cannot cancel an already committed outcome.
- No `clinical_dictation_proposals` insertion, `save_clinical_dictation_action`, encounter/problem mutation, signature, outbox, certificate, export or public link. A future reviewed_recap note adapter requires separate explicit selection/provenance/policy contract; no automatic clinical context insertion.

## Source synchronization — implementation proof still required

Membership checks must serialize appends and updates, not only compare signed encounter versions. DB audit found native problem writes lock pets and addendum inserts lock their parent encounter **before** an AFTER-write source epoch. Acquiring native-source FK/row locks after that epoch can deadlock, including implicit FK KEY SHARE checks.
Selected structural rule: **no native-source FKs**, including job/manifest/epoch pet_id and source encounter/addendum/problem IDs. Retain immutable canonical UUID/version/hash snapshots; RPC validates saved pet/client existence, exact patient linkage, eligibility and current staff authority. Native pets are undeletable through the normal workflow; retained snapshots do not depend on source-row FK retention. Under the epoch lock, read all identity/membership/content in one fresh plain SELECT without acquiring canonical source row/FK locks. New private-table dependencies need consistent job/epoch lock order. Initialize/backfill an epoch for every saved patient, create it on pet INSERT and fail closed if missing. Mutation families are pets, clinical_encounters, clinical_addenda, patient_problems and ezyvet_problem_extractions link eligibility. Capture/guard RPCs are VOLATILE/default under READ COMMITTED; saved-manifest-only projection may be STABLE. Private-row lock order and epoch synchronization remain design only until observed concurrent-write tests pass; do not claim runtime correctness yet. Existing public writers operate on one existing patient; future/arbitrary multi-patient SQL needs a separate ordering proof. For extraction changes derive the affected pet from actual patient_problems.pet_id, not the extraction row's independently stored pet_id. Recompute the complete selected source set after every wait.

Acceptance evidence: wrong patient/operator/session, archived/deceased history, complete addendum groups, outside-linked exclusion, stale/mixed chronology, exact citations, hostile source instructions, bounded refusal, source-write lock races, cancel/dispatch/review races, lost acknowledgements, populated restore, zero canonical clinical/outbox writes, desktop/390px and separate bounded synthetic-provider fidelity evaluation. No PDF/OCR/URL ingestion or additional native adapters are included.
