# 5A1 server boundary — implementation design

## Bounded operations

Use two reviewed operation types: `namespace` and `package`. Each packet requires exact actor/action UUID, immutable request, review_note and attestation. Namespace identifies supplier + account_label + catalog_scope, with explicit active state. Immutable namespace identity cannot change after first review; retirement/reactivation produces a new version. Package identifies an existing catalog product, reviewed clinical label/manufacturer/strength/form, purchase unit, exact conversion and identifiers. Each package version captures expected catalog product version/canonical stock unit. This metadata never changes stock,lot,price,invoice or historical treatment.

Package identifiers are an explicit bounded array(max50): supplier_sku/supplier_barcode require namespace ID and exact reviewed namespace version; GTIN uses global scope and normalized validated14-digit value. Preserve original source text separately. Namespace/GTIN/manufacturer/product identity must not be conflated. Same global identifier cannot silently map to a different active package. Same supplier SKU in two namespaces is distinct. Lookup without a selected supplier namespace can return multiple candidates; never select the first automatically.

## Private model

Six additive RLS tables, all direct PUBLIC/anon/authenticated/service grants revoked:

- `inventory_identity_entries`: stable namespace/package identity and current version pointer; product FK for package; created actor/time.
- `inventory_identity_versions`: immutable version definition,source product snapshot,actor/session,time; unique(entry_id,version) and deferred head↔entry/version consistency.
- `inventory_identity_bindings`: current active identifier index,unique(kind,namespace_key,value); references exact package/namespace versions. Historical assignment lives in immutable package versions. Retirement removes current bindings only,not history.
- `inventory_identity_reviews`: immutable owned prepared request,operation,actor/session,15-minute expiry.
- `inventory_identity_actions`: immutable exact saved receipt tied to original review; actor/session/request checks.
- `inventory_identity_cancellations`: immutable owned cancellation,including missing-preparation outcome,so lost transport cannot resurrect discarded work.

Review receipt freezes old version and original request,even after another reviewer changes the current mapping. No raw source file belongs here; later bounded import captures private actual file bytes/hash and adapter/source-row provenance separately. SQL constraints,not a frontend assumption,govern exact quantities/ratios and identifier contexts. Update/delete/truncate protections preserve immutable evidence; mutable head/current-index projections remain privately maintained.

## APIs and authorization

Private guard calls existing clinical staff authorization plus `next_visit_review_session`; current request must be authenticated and p_actor_id must match auth.uid. Namespace/package prepare/execute require current ADMIN/DVM,active profile and real unexpired matched Auth session. Recheck after every potentially blocking lock and immediately before recording the action. STAFF/TECH have explicitly authorized lookup/history reads and own receipt recovery; service/anonymous cannot review or use staff APIs. Actor/session evidence is recorded for each new version; shared practice metadata can be revised by another authorized reviewer under their own identity.

Authenticated RPCs:

- prepare_inventory_identity_review(actor,action,operation,request)
- read_inventory_identity_review(actor,action) — owned read-only original recovery
- execute_inventory_identity_review(actor,action)
- cancel_inventory_identity_review(actor,action) — cancellation returns saved receipt if commit already happened
- list_inventory_identities(kind,search,cursor,limit) —1..100,opaque UUID continuation
- read_inventory_identity(id) — current and bounded immutable history
- lookup_inventory_identifier(kind,value,namespace_id,limit) — candidate array,never stock posting

Only these endpoints get authenticated EXECUTE. Private validators/materializers/projections stay owner-only. Do not reuse or expand the unrelated operational-task mutation protocol. Narrow typed RPC bridge/Zod leaves autogenerated types untouched. UI uses the existing exact prepared-action experience,owned token-free pointer,recovery-first reload,dirty-navigation guard and actor-change checks.

## Lock/retry semantics

Actor quota lock → original action UUID → entry identity → distinct referenced namespace identities in sorted order → existing catalog product SHARE → current bindings in deterministic order. Existing stock writers do not acquire these metadata locks,so mapping work adds no product/lot inversion. Unique binding key insertion arbitrates collisions between packages. Recheck current namespace version/active state,package expected version,product version/kind/unit and session after waiting. Preserve exact old committed receipt before freshness checks; changed action request/actor fails23505. Failed materialization rolls back all head/version/index/action changes. Unknown acknowledgement retains original UUID/request; recovery never executes it. Pending-review quota32 per actor,request byte/array/text ceilings and2s lock/5s statement budgets are explicit engineering bounds.

Namespace retirement makes its bindings ineligible immediately. Reactivation under a new reviewed version does not silently restore older mappings; package mappings must be reviewed against that version. Package retirement removes only its current lookup bindings. Historical records and original receipts remain readable. Catalog product changes make a proposed package review stale; re-review before applying. Do not automatically change existing selling prices or units.
