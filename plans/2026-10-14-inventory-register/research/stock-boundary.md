## Reliable shared enforcement point

All identified physical available-stock writes insert `public.inventory_movements`. There is no single stock-posting RPC/helper used by every writer. The reliable shared boundary is the table's `inventory_guard` BEFORE INSERT trigger plus a proposed deferred constraint trigger validating controlled linkage at commit. Attach enforcement here, not only to receive/dispense UI or one RPC. Existing native return linkage demonstrates the exact deferred-constraint pattern needed: a movement is inserted before its event/link, then the constraint validates the completed transaction (`supabase/migrations/20260916090000_native_dispense_returns.sql:33`, `:43`; `supabase/migrations/20260916094500_native_return_reconciliation.sql:209`, `:218`).

Current inventory guard is the original definition at `supabase/migrations/20260913000000_inventory_billing.sql:59`, patched for native return event timestamps at `supabase/migrations/20260916090000_native_dispense_returns.sql:28`, then patched for compensation timestamps and discrepancy holds at `supabase/migrations/20260916094500_native_return_reconciliation.sql:200`. It derives actor from staff auth, makes movements/lots/treatments append-only, prevents deletion, freezes product kind/unit, and rejects new `dispense`, `adjust`, `native_return` movements on held lots. Receipts remain permitted during holds; `native_return_compensation` is permitted under its own linked-compensation safeguards. Inventory audit triggers are installed at `supabase/migrations/20260913000000_inventory_billing.sql:78`.

The controlled link should be mandatory only for products explicitly activated through reviewed opening count/provenance; old balances must not synthesize prior drug events. Validate exactly one immutable register movement per movement ID, matching actor, lot/container, signed quantity, canonical unit and physical time; validate the reverse link too. Existing `kind='dispense'` covers two workflows and `kind='adjust'` covers multiple meanings, so a trigger cannot safely infer clinical purpose from kind/reason text. Writers must supply an explicit validated event context in the same transaction. Witness records attest this committed immutable event and must never call a stock writer.

## Authorization, units and bypass limits

- `clinical_require_staff()` checks `auth.uid()` and `is_active_staff` (`supabase/migrations/20260912210000_clinical_core.sql:38`). The latter checks active profile + any ADMIN/DVM/TECH/STAFF role (`supabase/migrations/20260613183224_9575f409-8565-4e33-ab7a-1a004e11a670.sql:3`). Clinical-annotation role checks add DVM (`supabase/migrations/20260916083056_native_dispense_corrections.sql:23`); return policy configuration requires ADMIN **and** DVM (`supabase/migrations/20260928190000_no_retryable_sqlstate_for_permanent_conditions.sql:1034`). Anesthesia/treatment descriptive veterinarian names are not independent signing identities.
- Stock paths do **not** inspect JWT `session_id`, `auth.sessions`, expiry/revocation of the session row, or bind reviews/receipts to a live session. Elsewhere the new next-visit helper checks these explicitly (`supabase/migrations/20261013233839_next_visit_staff_recovery.sql:28`), but inventory does not call it. Rechecks after blocking operation locks and insert-trigger authorization are valuable; they are not a live-session guarantee. Controlled actor/witness authorization needs its own explicit policy and checks after waits.
- Ledger quantities are `numeric(14,3)`, balances are full `sum(quantity)`, stock unit is immutable **free text** on catalog (`supabase/migrations/20260913000000_inventory_billing.sql:2`, `:14`, `:67`; read model `supabase/migrations/20260913030000_inventory_read_models.sql:12`). Native quantities are exact decimal strings, bounded to `99999999999.999` and at most three decimals (`supabase/migrations/20260916072509_native_fulfillment.sql:65`). Base receive/adjust/treatment accept SQL numeric but reject NaN/infinity and unsupported precision before storage. Base frontend uses JavaScript `Number` (`src/hub/features/inventory/stock-policy.ts:5`); native fulfillment already preserves decimal strings. No package/case/vial-to-mL conversion, concentration model or canonical unit registry exists. Any future conversion must be reviewed and exact, rejecting unsupported precision rather than allowing column coercion to round.
- Public/anon/authenticated/service_role table writes are revoked; only staff-readable SELECT grants/policies exist for base inventory (`supabase/migrations/20260913000000_inventory_billing.sql:78`). RPC execution is granted to authenticated, revoked from anon/service_role (`:226`); native tables/helpers are similarly private (`supabase/migrations/20260916072509_native_fulfillment.sql:32`; return-v2 grants `supabase/migrations/20260916094500_native_return_reconciliation.sql:547`). No normal authenticated/service-role direct table stock-write bypass was found.
- Privileged owner SQL remains a meaningful test surface: current generic movement INSERT guard does **not** itself take the lot lock, enforce balance/nonnegative debit, require receive/dispense sign, reject raw precision before `numeric(14,3)` coercion, or require treatment/native-fulfillment link for generic `dispense`. It stamps actor using request claims, so a privileged fixture with staff claims can insert ordinary movements while bypassing RPC business validation. Existing native-return deferred constraints cover their specific kinds only. Base inventory also lacks a TRUNCATE guard (return/anesthesia tables have one). A controlled deferred link constraint must reject such direct INSERT attempts, not merely rely on ACLs. Superuser/owner ability to disable triggers is outside an application permission guarantee.

## Existing identifiers and supplier implications

- Reuse `catalog_products.id` UUID, immutable kind/unit, product version and manufacturer/name. No unique product-name rule; name match is not a medical identity. No catalog strength/form/package-size/purchase-cost fields, supplier table, supplier-SKU crosswalk, barcode/GTIN mapping or staged supplier-import model found in the current inventory schema/search. Native prescription strength/form are signed free-text prescription facts, not reusable product catalog identifiers.
- Reuse `inventory_lots.id` and its unique `(product_id, lot_number, expires_on, location)` tuple (`supabase/migrations/20260913000000_inventory_billing.sql:8`). Multiple physical containers can share this tuple; the current model cannot distinguish them. Add container identity instead of repurposing lot UUID or treating distributor SKU as container/barcode identity.
- Product search covers name/manufacturer only; lot search covers product name/lot/location (`supabase/migrations/20260913030000_inventory_read_models.sql:1`). New exact identifier resolution must preserve text/leading zeros, supplier+SKU namespace, barcode scheme/package identity and ambiguity handling. Catalog import must not call receive; apply should not silently change selling price or stock units. Real vendor mapping and scanner acceptance remain blocked on actual exports/labels/iPhone proof, not solved by synthetic fixtures.
