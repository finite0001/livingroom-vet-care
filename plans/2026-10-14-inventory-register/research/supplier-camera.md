This gives a concrete account-owner export to request; it does not establish a full catalog export, CSV option, column schema or API entitlement. Actual sample and online-account access remain pending. [MWI Online Store](https://www.mwiah.com/how-we-work/online-store), fetched live October 14; publication date not shown.
2. **Midwest catalog file export for this account remains unverified.** Public pages and bounded search/map did not establish a SKU/price CSV/XLSX download contract. DaySmart documents catalog product numbers and live price/availability through its enabled MWI/Midwest integrations. That proves partner functionality, not permission for LRV to use the same endpoints. [DaySmart supplier integration](https://help.vettersoftware.com/en/articles/9301102-ordering-inventory-through-mwi-patterson-or-midwest-veterinary-supply-formerly-victor-medical-integrations), fetched October 14.
3. **Real iPhone camera scanning remains a launch requirement.** Documentation supports the architecture but supplies no actual practice-device acceptance evidence. The selected decoder must remain provisional until real labels from both suppliers succeed on the intended iPhone/Safari over the deployed HTTPS origin.

## Native reviewed import contract

This is a proposed LRV contract, not a claim about vendor fields. Use separate MWI and Midwest adapters feeding one preview/apply boundary. Design it now; finalize provider adapters after real sample review.

| Field group | Required behavior |
|---|---|
| Source identity | Practice scope; provider ID; supplier account reference without credentials; file SHA-256; filename, byte size, exported/effective/imported times; adapter/mapping version; source sheet/row; original values; authenticated importer and reviewer |
| Crosswalk identity | Supplier + raw SKU string + relevant catalog/account namespace; canonical LRV product/package ID; match status and reviewed mapping version. Identical SKU strings at two suppliers remain distinct. |
| Clinical identity | Original product description; reviewed name, manufacturer, manufacturer item number, ingredient, strength/concentration and units, dosage form/route where available. Missing clinical details block an unsafe match. |
| Package and units | Supplier purchase unit, units/package and package size; canonical stock unit; dispensing unit; exact reviewed conversion numerator/denominator or fixed-precision factor. Cases/vials/tablets/mL must resolve explicitly; no factor of 1 default. |
| Identifiers | Separate supplier SKU, manufacturer SKU, GTIN/UPC/EAN, symbology and raw decoded bytes/text; package level and identifier provenance. Multiple identifiers may map to one package. A supplier's printed barcode is not presumed to be manufacturer GTIN. |
| Commercial data | Source cost as decimal string, currency, cost unit and effective date; explicit proposed cost changes. Supplier cost is not practice selling price; retail changes require independent review and preserve history. |
| Review/apply | New/update/unchanged/ambiguous/conflict/error decision; selected existing product/package; medical/package mismatches; reviewer/time; before/after values; source version used; apply idempotency key and committed result |

Keep raw identifiers intact. Normalize only under an explicit identifier-specific rule, recording both raw and canonical forms. Reject incompatible strength/form/package matches even when descriptions look similar. An ambiguous barcode opens the reviewed mapping flow; it cannot create a product or receipt automatically.

Stage then preview row errors, duplicates and proposed updates; default to no automatic medically significant merge. Apply valid reviewed rows atomically with stable identities, conflict detection against the catalog version reviewed and server authorization derived from session identity. A replay must return the prior result or recognized unchanged rows, never duplicate products. A re-export with identical SKU values and newer costs must update the crosswalk/cost proposal rather than create another product. Missing rows are not deletion instructions.

Importing catalog rows never posts stock. Actual receipt collects location, quantity, lot/expiry/container as needed and uses the current receive/stock RPC boundary. Scanning selects a product/package and offers any decoded fields for confirmation; it never changes stock from a frame callback. Preserve the existing product/billing IDs and confirmed transaction identities.

## CSV and Excel parsing decisions

Verified MWI Excel means the plan must explicitly accommodate its real workbook, or document an owner-approved conversion with an exact sample comparison; a CSV-only importer cannot silently claim it imports MWI's documented format.

- **CSV candidate:** exact `papaparse@5.7.0`, released August 24, 2026, MIT and no declared runtime dependencies in the [official registry record](https://registry.npmjs.org/papaparse/5.7.0). Keep `dynamicTyping: false`; apply Zod schemas and decimal/string conversion after parsing. Quoted delimiters and multiline descriptions require a real CSV parser. [Papa Parse documentation](https://www.papaparse.com/docs).
- **Excel candidate:** official SheetJS CE `0.20.3` vendor tarball, as specified by the [maintainer's installation documentation](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/). Pin the exact artifact, record integrity/license and vendor or lock it reproducibly; lazy-load only for import. This remains provisional: direct artifact retrieval returned HTTP 403 in this environment, so current tarball contents, integrity and dependency audit were not verified. Check those before adoption; do not suppress a scanner warning solely because a vendor calls it false positive.
- **Reject `npm install xlsx` as the default.** Public npm's latest is still `0.18.5` (March 24, 2022). [GitHub advisory GHSA-5pgg-2g8v-p4x9](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9) identifies ReDoS below `0.20.2` and explains the patched package is unavailable there. The [official npm record](https://registry.npmjs.org/xlsx/0.18.5) was checked October 14.
- **ExcelJS is not the recommended default:** public release `4.4.0` dates to October 19, 2023 and brings multiple ZIP/stream/archive dependencies. It may parse XLSX but does not establish coverage of MWI's unknown Excel format. Do not assume it is maintained or safe based on popularity. [Official repository](https://github.com/exceljs/exceljs), [registry](https://registry.npmjs.org/exceljs/4.4.0).

For Excel, retain cell type, raw value, number format and displayed text. [SheetJS cell model](https://docs.sheetjs.com/docs/csf/cell/) distinguishes these. Prefer true string identifiers. A numeric cell formatted `000000` may preserve meaningful displayed zeros, but the adapter must verify that using an actual sample and show discrepancies. Numeric scientific notation, long identifiers beyond exact spreadsheet precision, formulas in identity/cost fields and mixed cell types need errors/review; do not invent digits lost before import. For CSV, never parse SKU or barcode values through JavaScript `Number`.

Limit input bytes, sheets, rows, columns and decompressed workbook content using budgets derived from real exports; execute parsing in a cancelable worker where appropriate. Never evaluate formulas or fetch embedded/external links. Render source cells as text. Protect exported error reports from spreadsheet formula injection. Browser preview validation improves UX; server validation and authorization decide what may commit.

## Current iPhone Safari capture and decoding

**Capture:** `navigator.mediaDevices.getUserMedia`, `enumerateDevices`, media track capabilities/constraints and `HTMLVideoElement` are the relevant APIs. Official [WebKit WebRTC guidance](https://webkit.org/blog/7763/a-closer-look-into-webrtc/) documents HTTPS, camera permission and track mute/unmute behavior. It dates to 2017 and is architectural guidance, not a current device proof. The [current compatibility source](https://github.com/mdn/browser-compat-data/blob/main/api/MediaDevices.json) reports Safari capture since 11 with iOS mirroring Safari, checked October 14. Use the [current W3C capture specification](https://w3c.github.io/mediacapture-main/) for constraints and track lifecycle, rather than deprecated `navigator.getUserMedia`.

**Native detector:** the [current compatibility source](https://github.com/mdn/browser-compat-data/blob/main/api/BarcodeDetector.json) marks Safari support since 17 behind the Shape Detection API preference, with iOS mirroring Safari. [WebKit issue 281848](https://bugs.webkit.org/show_bug.cgi?id=281848) is open/NEW and contains reported iOS failures from Safari 18 through an iOS 26 beta; last visible comment July 21, 2026. Reports are not definitive tests of today's practice device, but they rule out relying on API presence alone or requiring users to enable experimental flags. Optional native acceleration requires a real decode health check and known-format coverage; default to the accepted bundled decoder.

| Approach | Exact researched pin and maintenance evidence | Runtime/dependency/license tradeoff | Recommendation |
|---|---|---|---|
| Direct `zxing-wasm/reader` | `zxing-wasm@3.1.5`, published October 6, 2026, recent upstream release | Reader WASM approximately 1.04 MiB; application owns camera/frame loop. MIT wrapper plus Apache-2.0 ZXing-C++/C++ wrapper. Registry lists type-fest/@types/emscripten; verify lock and Node/TS typing compatibility. | Provisional first choice. Avoid a redundant React scanner wrapper; retain raw bytes/format where available for identifier/GS1 handling. |
| Explicit `barcode-detector/ponyfill` | `barcode-detector@3.2.2`, published August 16, 2026; exact dependency `zxing-wasm@3.1.3` | API-compatible convenience, extra wrapper; MIT plus core licenses. Its bundled WASM must match 3.1.3, not direct reader 3.1.5. | Suitable alternative if detector-shaped results fit the workflow. Do not add both by default. |
| `@zxing/browser` + `@zxing/library` | Browser `0.2.1`, July 6, 2026, peers library `^0.23.0`; library `0.23.0`, April 29, 2026 | Browser MIT; library Apache-2.0, declares Node >=24 and maintenance-only development. Pure JS avoids WASM hosting but still needs iPhone proof and adds peer maintenance burden. | Not default for this Node 22 project. Existing familiarity is not proof of current maintenance or compatibility. |

Evidence: [ZXing WASM maintainer README](https://github.com/Sec-ant/zxing-wasm), [3.1.5 registry metadata](https://registry.npmjs.org/zxing-wasm/3.1.5); [ponyfill documentation](https://github.com/Sec-ant/barcode-detector), [3.2.2 metadata](https://registry.npmjs.org/barcode-detector/3.2.2); [browser registry](https://registry.npmjs.org/@zxing%2fbrowser/0.2.1), [library registry](https://registry.npmjs.org/@zxing%2flibrary/0.23.0), [library maintenance statement](https://github.com/zxing-js/library). All checked October 14. Package sizes above are uncompressed WASM figures, not measured transferred bytes or device latency. No install/audit or physical-device test was performed.

For the WASM option, serve the exact reader asset from the app origin, with version/content hash, correct MIME and matching wrapper; override the default CDN location. Keep licenses/notices with the distributed app. Lazy-load on opening Scan; show initialization failure clearly. Check actual Vite asset handling and deployed CSP/WASM compilation; do not solve failure by broadly allowing JavaScript eval. Pin npm lock integrity and decoder/WASM provenance together. Do not auto-update a tested scanner version at runtime.

## Required scanner interaction and acceptance package

On a user-initiated Scan action, request video only with preferred rear-facing camera and non-exact adaptable resolution. Bind one stream to a muted `playsInline` video; Apple's [Safari video guidance](https://developer.apple.com/documentation/webkit/delivering-video-content-for-safari) documents inline playback. Do not assert torch, focus, zoom or a particular rear lens exists; inspect track capabilities and test the real multi-camera device. Stop existing tracks before switching cameras. Provide guided framing, cancel, retry and manual lookup recovery.

Use a bounded crop/frame loop with one decode in flight, preferably off the UI thread. Pause/stop on hidden page, close, navigation and unmount; ignore late permission/decode results after cancellation and stop any late stream. Handle permission denial, no device, busy device, track ended/muted, WASM load failure, rotation, background/lock/return and camera switching. A success pauses scanning and shows description, strength/form, package, location/lot/expiry/quantity for review. Multiple codes or ambiguous mappings require selection; debounce by scan session without suppressing an intentionally repeated later transaction.

Only treat a label as GS1 when symbology/payload evidence establishes it. Official [GS1 AI reference](https://ref.gs1.org/ai/) specifies `01` GTIN, `10` lot and `17` expiry (YYMMDD). Preserve separators and raw content; validate variable-length fields and applicable date semantics. Ordinary UPC/SKU codes do not imply lot or expiry. GS1 decoding is not approval to receive a controlled drug; confirmed stock writes still use the authoritative movement/register boundary.

Before launch, staff must execute a device matrix with recorded iPhone model, iOS/Safari build, HTTPS deployment/version, decoder/WASM hash, actual label type and expected identifier/product/package. Use untouched provider exports and real manufacturer/distributor labels from **both** suppliers. Include small curved vial labels, cases/tablet packs, glare/damage, unknown and ambiguous identifiers, leading-zero identifiers, differing strengths/package sizes and GS1 examples if present. Verify permission denial/retry, background return, navigation cleanup, repeated frames, intentional repeated scan and confirmed receive/dispense transactions. Record measured acquisition/decode time and failure rates with Dr. Edler/staff acceptance criteria agreed before trials. Inspect camera indicator after closing. Automated fixtures supplement this evidence; mock streams, static label images, desktop decoding and manual lookup do not satisfy the real-camera gate.
