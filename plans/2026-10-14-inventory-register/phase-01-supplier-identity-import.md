## Architecture and implementation

1. Add private RLS tables for versioned product packages, supplier namespaces/crosswalks, identifier assignments, exact prepared actions and immutable review receipts. Reuse existing inventory product UUIDs; record canonical stock unit separately from purchase/dispense units. Conversions are positive fixed-precision/rational values with validated capacity; never silently default to 1. Existing stock/billing writers continue using their immutable original units and prices.
2. A supplier SKU is text scoped to supplier/account/catalog namespace. Manufacturer SKU, GTIN/UPC/EAN and supplier-printed barcode are separate identifier types with original provenance. Preserve leading zeros, raw bytes/text and package level. Ambiguous or conflicting identifiers return explicit candidates; never auto-select by description or create a product from a scan.
3. Reviewer mutations use ADMIN/DVM plus active profile and exact live Auth session, rechecked after locks. Lookup is explicitly authorized clinical staff. Implement dedicated inventory prepare/execute/recover contracts using the established exact-receipt pattern; do not extend the operational-task protocol with unrelated inventory operations. Receipt freezes original UUID, actor, expected mapping version and normalized request. Original recovery is read-only; retries with changed request fail. Unknown acknowledgement keeps the original pointer, not a new apply ID.
4. Order locks consistently: operation identity → package/crosswalk identity → product in the order compatible with current stock product locks. Recheck product kind/unit and mapping version before commit. Mapping retirement is append-only, preserving historical scans/imports. Enforce uniqueness/immutability at the database boundary, not only in UI.
5. Add bounded product/package lookup and reviewer dialog to the existing Inventory page. Show product, strength/form, purchase package, stock unit and reviewed conversion together. Preserve dirty-draft navigation, actor-change recovery and mobile behavior. Metadata UI does not expose service credentials or developer IDs to staff by default.
6. Separately add private import-file capture and immutable preview batches. Record source SHA256, file bytes/name, provider/account scope, original cells, source row/sheet, adapter/mapping version and row-level proposals/errors. Parsing in a cancelable worker does not authorize apply; server validates every row and approved mapping. No network/formula execution or arbitrary workbook links.
7. Finalize MWI adapter against its actual List Excel schema. Finalize Midwest only against an actual supported export/interface. Preserve raw and displayed spreadsheet cells: leading-zero formats need review, numeric precision already lost cannot be reconstructed, formulas in identity/cost fields fail review. CSV identifier strings never pass through Number. Actual workbook artifact provenance and input/decompressed limits remain prerequisites.
8. Prefer official SheetJS0.20.3 only after acquiring/verifying its supported artifact and exact lock/integrity/build/audit; research download403 means this is unresolved. Do not install npm xlsx0.18.5. PapaParse5.7.0 with dynamicTypingfalse is the researched CSV option. Do not claim a CSV-only synthetic adapter completes MWI Excel import.
9. Apply approved product/crosswalk changes in bounded atomic groups, with stable source-row identity and exact durable receipt. Repeated same file/row cannot duplicate products. Preview stale due to catalog edits must be reviewed again. Any existing selling-price change is a separate explicit proposal, with effective time and unchanged historical invoice lines. Supplier cost updates are not selling-price updates.
10. Import never receives goods, creates inventory_movements, changes lots or posts charges. Actual receipt separately records lot, expiry, container, location and confirmed quantity through existing physical-stock boundaries.
