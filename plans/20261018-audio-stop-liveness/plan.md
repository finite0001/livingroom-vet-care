# Bound local recorder finalization

Parent source: `a11df554df0f01094a566e65936e8f80bb5576d9` (PR277 quote-anchor work). This isolated increment does not modify that branch or its source-bound evidence.

Problem: `ClinicalPcmRecorder.stop()` starts an acknowledgement timeout but awaits AudioContext.resume() before observing that promise. A pending resume can stall Stop, delay disposal and leave a rejected acknowledgement unhandled. The stable Web Audio resume algorithm permits pending resume promises when starting is not allowed: https://www.w3.org/TR/webaudio-1.0/ . No physical Safari failure has been observed.

Implementation scope: recorder.ts only, plus focused actual-class synthetic tests. Preserve pause/resume API, worklet, strict 16 kHz/mono/16-bit format, min/max/WAV validation, no persistence/upload/provider call. No statechange/mute watchdog change. Convert the constructor parameter property to an equivalent explicit assignment so Node's existing strip-types test runner can import the actual class without dependencies.

Use one 1500 ms finalization deadline covering resume, worklet completion and context-close settlement. Observe every promise immediately. A timeout/rejection/cancellation must synchronously stop tracks and detach/close the worklet before settlement; late resume or ACK cannot post more work or publish a clip. External dispose cancels an in-flight finish. No automatic retries. Deadline failure remains a visible failure through the existing UI.

Verification: actual recorder with synthetic MediaStream/AudioContext/worklet only; normal/paused/limit stop and byte-level WAV preservation; resume rejection; never-resolving resume; missing ACK; late resume rejection/ACK after disposal; external dispose; pending/rejected close; repeated disposal. Assert bounded settlement, stopped tracks, disconnected nodes/closed ports, no unhandled rejection and no real capture/network. Run focused audio tests, repository lint/typecheck/tests/build as appropriate. Physical iPhone/Safari and clinical policy acceptance remain separate.

Status: implemented in the isolated worktree. The recorder snapshots the active context/node, rejects concurrent Stop, observes the resume chain immediately, and races the acknowledgement and disposal settlement against one original 1500 ms deadline. `dispose()` rejects a dedicated cancellation signal kept active through the entire Stop operation, including context-close settlement. Stop uses an internal resource-release helper so its own normal cleanup does not cancel itself. External disposal stops tracks and detaches/closes worklet resources; a final cancellation check covers cleanup/cancellation microtask ordering. A resume continuation checks disposal and context/node identity before posting Stop. No additional retry or upload is introduced.

Seventeen focused tests import the actual class and supply synthetic browser interfaces. They cover byte-for-byte PCM preservation, normal and paused Stop, an already completed limit, resume rejection, never-settling resume with late resolve/reject, missing/late ACK, external disposal before/during resume, shared resume/close deadline, close rejection, concurrent Stop, minimum-duration validation, external disposal during pending close with late close resolve/reject, delayed normal close, and idempotent disposal. Existing model/worklet tests continue to cover format, duration limits, and paused-sample exclusion.

The pending-resume test was also run against the exact parent recorder, with only its TypeScript constructor parameter property converted to an equivalent explicit field and import paths relocated for Node. It fails with Node TAP `failureType: unhandledRejection` from the original acknowledgement timeout. The same scenario passes with this fix. No actual browser capture or physical interruption was exercised.

The existing `ClinicalDictationAudio.finishRecording()` catches rejected Stop, displays its error, and resets the finalizing/locked state in `finally`; no UI change is needed for the bounded failure to become actionable. The deadline is a JavaScript timer and therefore cannot promise execution while the browser event loop is frozen. Start/resume outside Stop, AudioContext state-change monitoring, track mute detection, and physical Safari acceptance remain separate work. The existing visibility-change pause behavior is preserved.

No hosted, provider, activation, real microphone, or account operations were performed. Final verification results and source hashes are retained in `verification.json`.

Review follow-up: the first local commit (`5e145c796a8c0e4e3e8495db92ccad84521fbf6d`) cancelled only before ACK. Independent review identified that external disposal during a pending context close could still allow Stop to return a WAV. The two new cancellation tests fail on that commit because Stop remains pending instead of rejecting immediately after external disposal. The dedicated cancellation signal now rejects Stop before close settles, prevents any WAV result, and continues to observe late close resolution/rejection. A separate delayed-normal-close test retains the valid success path. This correction is a new commit; the initial regression evidence remains intact.
