# Phase 3B.3 — frozen synthetic call fidelity preparation

## Scope

Prepare offline, wholly fictional evaluation material for the production call-note request and response contracts. No hosted reads or writes, network calls, keys, activation, paid requests, clinical acceptance or deployment are part of this package.

## Implementation

1. Freeze ten fictional household-call scenarios and mandatory/forbidden meaning inventories before any future provider request. Include multiple pets, uncertain speakers, corrections and negation, historical/current statements, exact doses, absent measurements, treatment status, midnight/DST/unknown start, hostile instructions, and comparisons that require multiple segments.
2. Construct each retained transcript through the production capture adapter with an injected local response stub. Build every request with the production request builder, and retain exact serialized requests plus prompt, template, vocabulary, source and code fingerprints. Synthetic context hashes are offline fixture hashes, never evidence of SQL authorization or a hosted manifest.
3. Export an immutable bundle with no overwrite. Import exactly one retained raw result per case, including refusals, invalid JSON and transport failures. Fail closed for missing/duplicate cases, request mismatches or bundle tampering.
4. Produce a review packet and pending adjudication form containing raw outputs, parsed claims, each claim's own supports, assembled selected-patient SOAP, expected/forbidden meanings and explicit per-claim/per-support decisions. Structural validity never grants a semantic pass. Require all questions, nonempty rationales and named reviewer before accepting adjudication; any failed transport/contract/meaning prevents an overall pass.
5. Verify deterministic export, production contract acceptance for every request, and missing/duplicate/tampered import/review rejection. Preserve structurally valid semantic negative controls as proof of the validator's boundary.

See the [protected transport design](provider-run-design.md) for the proposed next implementation, one-shot guard, partial-response evidence and pricing/cleanup limits. It authorizes no hosted or paid operation.
