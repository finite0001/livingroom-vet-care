# Isolated diagnostic renderer

Package 3B2A proves rendering/admission. Package 3B2B adds default-off private processing and registration, with an operator-invoked coordinator. No API route, queue consumer, scheduler or clinical worker policy is activated. See the [plan](../../plans/2026-10-11-diagnostic-pdf-renderer/plan.md) and [native evidence](../../docs/launch-evidence/2026-10-11-diagnostic-pdf-renderer.md).

The template accepts trusted already-frozen reviewed source data, not arbitrary public HTML. The coordinator must persist the full manifest/history/provenance and choose an approved immutable image digest before production use. Report HTML is deterministic; Chromium PDF timestamps can vary. Captured PDF recovery must therefore reuse saved bytes, never re-render them.

The image's default root user is for the Vercel SDK's trusted setup. The actual worker is invoked as `lrv-render` and fails unless UID 12001, sudo denied and effective Chromium namespace/seccomp sandboxing are observed. A direct default-root Docker invocation intentionally fails. No `--no-sandbox`, capability elevation, privileged mode or host IPC fallback is permitted.

The Docker CI harness runs natively on amd64 with read-only root, no network, dropped capabilities, no-new-privileges and bounded private scratch. Chromium's XDG configuration/cache are directed into that scratch, preserving the read-only home/root filesystem. Its seccomp policy is from [Playwright 1.63.0](https://github.com/microsoft/playwright/blob/v1.63.0/utils/docker/seccomp_profile.json), adding `chroot` for Chromium's private user namespace without adding a capability. The accompanying Playwright license is Apache 2.0. Vercel uses its own Firecracker boundary; native hosted proofs verify actual browser sandbox status and raw DNS/TCP/metadata denial separately.

PDF admission is limited to the pinned producer's observed PDF 1.4 subset. It is not a general sanitizer, digital signature, clinical approval or export authorization. Rejecting an unsupported valid PDF is intentional. Runtime upgrades require a new image digest, source/binary/font provenance and execution/admission proof; apt packages may change between Dockerfile rebuilds.

The [3B2B coordinator](processing.ts) freezes deterministic HTML/history before rendering, independently validates first capture and recovered bytes, reserves a no-overwrite private path, streams actual Storage readback and registers the exact object UUID/creation/update time/body generation and byte hash. Original capture and replacement processing actors remain separate. Saved receipts are historical evidence; `object_present` is a separate current metadata projection, and `registered_unavailable` never automatically re-renders or overwrites bytes. Staff downloads and export eligibility remain false.

`node --experimental-strip-types scripts/diagnostics/process-private-pdf.ts JOB_UUID` is an operator-only command. It expects `DIAGNOSTIC_PDF_BACKEND_URL` and `DIAGNOSTIC_PDF_SERVICE_KEY` in the trusted parent process, plus project-scoped Vercel Sandbox authentication. It accepts no HTML, URLs, object paths or commands from callers. Both unseeded worker/runtime policies must explicitly match the accepted image/source/font/settings fingerprints; otherwise it returns `off`. Every invocation may wait for a prior 90-second lease to expire; retrying the same job recovers the immutable manifest/capture. Never put these keys in frontend variables or guest environments. It is not a hosted scheduler deployment.

Failures persist only one of four bounded generic codes when the current processing lease still permits it; provider exceptions and chart text are not written into the processing error field. A lost registration response may already be committed, so a superseded/stored claim cannot be marked failed. Reserved but unregistered objects remain private; cleanup and object-body backup/restore require later explicit contracts.

Verification: `python3 -B tests/diagnostics/pdf-registration-disposable.py --run-synthetic-local --include-sql-regression` uses a uniquely owned localhost Auth/Storage runtime and genuine native Sandbox bytes. CI explicitly sets `DIAGNOSTICS_RENDERER_MODE=docker` on native amd64, using the same real Auth/capture/Storage/coordinator flow inside a credential-free restricted renderer container. The SQL/DTO fixtures exercise authorization and serialization only; they do not establish actual parser or HTTP Storage readiness.
