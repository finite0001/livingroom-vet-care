# Prospective count wire components

This unmounted software slice implements local DTO admission, public request/receipt framing and immutable saved-reply binding. It performs no network call, creates no operation, and supplies no authentication, role, site, snapshot membership, count policy, observation-age or physical evidence. No count table, facade, route, grant or migration is added. The SQL file is an owner-only temporary parity component ending in ROLLBACK, not an installed application interface. The source freeze was grammar-only. A later isolated local PostgreSQL17 run passed the temporary parity component and eight deliberately injected faults; its public, non-sensitive evidence is in evidence/controlled-count/wire-parity-v1. This does not prove a count backend, application resource budget or public error privacy.

Authority is the prospective count-record V2 and count-wire V2 contracts. Exact wire contract SHA256 is `e239722e82cc7e6ab6ff8a4587593084f79fbf2863aec04825d5760b971dbdbf`, binding `3094227f2f6976bbbb0a651634e1897ce201ce13c6b33fa83973ae572568b7c3`; independent direction review is `b8a49ea5680d75e3f0b29d6e118936be18f72a3854f1459836a7621cde2aae80`. Those are design inputs, not deployment or runtime acceptance.

`count-request-schema.ts` admits the six exact request shapes through `parseCountRequest(action, value)` or duplicate-aware `decodeCountRequest(action, bytes)`. The endpoint action is a primitive fixed literal outside the request. Fixed object field sets, per-string UTF-16/UTF-8 ceilings, array cardinalities and own enumerable data descriptors are checked before child traversal and Zod. The fixed shape limits bound subsequent walking; accessors are not read, sparse arrays/custom prototypes/symbols/unknown fields/cycles refuse. Input is copied and the parsed result deeply frozen. Structural reflection is not a claim that arbitrary hostile JavaScript Proxy traps can be sandboxed or have no side effects. No unsafe generic structural/hash validator is exported.

Statements require sorted unique canonical lowercase cell/container UUIDs, exact nonnegative three-decimal strings, the manual_count method and Gregorian UTC timestamps retaining six microsecond digits without Date conversion. Findings preserve array order and exact text. The literal27-scalar blank set, NUL/surrogate refusal and UTF-8 caps apply without trimming, UUID conversion, Unicode normalization, sorting or quantity conversion. Limits are512 quantities,512 checks,32 findings,512 description bytes,1024 reason bytes and262144 parsed-JSONB-text bytes. Complete server membership—including zero cells and empty onsite containers—remains server authority; an empty locally valid array does not prove an empty scope. Live input caps do not truncate or validate movement history.

The bytes decoder has its own upfront byte ceiling, depth/node/member ceilings, fatal UTF-8 decoding and duplicate-key rejection. Only numeric tokens whose PostgreSQL17 numeric output is exactly `1` can reach the literal schema version. Thus raw `1e0`/`0.1e1` can normalize to that parsed constant, while retained scale `1.0`/`10e-1` refuses. Direct JS object admission can see only Number1, not its discarded source spelling: use the bytes API when admitting raw JSON. Neither API claims to recover a spelling already lost by JSON.parse or JSONB. JSONB cannot detect upstream duplicate keys already discarded; the local bytes decoder deliberately rejects them before loss.

`count-wire.ts` exports count-specific request/receipt byte and SHA256 APIs and saved/not_found/not_ready verification. The framing is domain+NUL+the closed value frame: ASCII key order, exact UTF-8 lengths, retained array order and schema-version bytes hexadecimal69313b. A receipt validates its excluded own digest as a primitive before omission. SHA256 uses the browser Web Crypto implementation, with data snapshotted before the first await. No generic private-record hash, caller-selected domain, nonce generator or private opaque-reference reconstruction API exists.

Saved replies have exactly the closed envelope and eight receipt keys, with four action/result-kind variants. Verification recomputes the request and public receipt digests and binds action, original operation/count/actor and result ID to the retained original mutation. The server's opaque commitment is structurally checked but its concealed private record/nonce is not reconstructed. A later session may validate the same historical receipt without adding or rewriting a session field. Public success binding does not confer current read authority. Explicit recover and read requests are nonwriting values; not_found is separately bound to recover IDs, and not_ready to an explicit finalize count. No optimistic success, new operation or automatic retry is performed. A full count read DTO is deliberately not invented here.

Every saved/recovered receipt remains thin: no expected quantities, other observer findings/quantities, boundary hash, private snapshot, nonce, session or comparison is permitted as an extra field at any level. This local closed-schema rejection does not implement the universal server P0001/deferred/serialization failure boundary. That still requires new DDL/facades, forced in-handler reciprocal checks, complete guarded commit tails and actual hidden-value PostgREST/error/lost-response tests. Count commissioning, two genuine distinct actors, browser workflow, investigation/holds and physical/hosted activation remain separate unfinished gates.

The fixtures are explicit synthetic unit data, not accepted Auth or physical count corpus. Independent V2 review vectors supply fixed request/four-receipt digests;111 contract-unit request cases supply input parity expectations. Node tests cover hostile own/nested getters, caps before traversal, exact numeric aliases, Unicode/time boundaries, every retained mutation field, recommitted receipt mutations, forbidden concealed fields and pre-await snapshot isolation. The SQL component independently implements parsed-JSONB request validation and byte framing, with the same fixed vectors and rollback-only assertions. Its initial source grammar/PL parsing is distinct from the later local PostgreSQL parity run. That run validated111 request vectors and all four fixed receipt commitments, with an8s component statement timeout; the complete staff/browser/count-backend resource gates remain unfinished.


## SQL proof successor

The original N V1 remains frozen under its SQL-proof HOLD: its negative harness caught every ordinary exception as an intended refusal. This successor changes only that rollback-only proof boundary. All111 current raw vectors are independently classified as valid JSONB casts; casts now occur outside the refusal handler. The typed component's sole admitted rejection is P0001 with exactly Invalid count component and empty DETAIL/HINT. Other codes, messages or diagnostic fields propagate. This remains a test component, not the future public P0001 failure-privacy facade. The subsequent disposable run exercised unknown-function/column/data/internal/wrong-message/detail/hint and bad-raw-cast propagation. Exact primary diagnostics and a unique negative-target notice were required, and original selected state was unchanged after every fault. This is a strict test-oracle check, not a universal public diagnostic-privacy proof. The TypeScript modules and original fixture values are unchanged. No observed error is adopted as an expectation, and no broad22xxx or parser-error allowance is introduced.
