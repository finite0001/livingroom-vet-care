# Daily communications — implementation package 2A

Implements N12 (Daily communications) from the October 8 feedback plan. Based on merged Whogot `fa8f286446b4c387226cb58f875c7147ec1661eb`.

## Delivered behavior

- Preserves `/hub/deliveries`, with shared navigation/mobile label, document title and heading **Daily communications**.
- Staff-only server read model combines canonical `communication_outbox`, retained `outbound_deliveries`, scheduled/blocked care jobs and appointment reminder jobs. Exact same-channel message associations, matching provider delivery identity and canonical reminder links suppress duplicate retained rows. Recipient/name similarity does not establish duplication.
- Defaults to today's America/Denver date. Inclusive day/range (up to 366 days), channel, status and patient/client name search run on the server. Deterministic keyset pages contain at most 100 rows (UI requests 50).
- Scheduled, queued, processing, accepted, delivered, failed, uncertain, suppressed and cancelled are distinct. Provider acceptance is explicitly delivery-unconfirmed. Historical SENT without linked delivery evidence remains uncertain. Final preflight rejection before an attempt is suppressed; invalidation after an attempt starts preserves actual acceptance/delivery status.
- One communication row contains attempt count; expanded history retrieves individual canonical attempts. No second dispatcher or send path was created. Canonical failures/suppression link administrators to the existing reviewed retry workflow. Retained FAILED rows use their original version-checked retry RPC; UNKNOWN/uncertain rows never offer a blind retry. Scheduled/queued retained rows use their original cancellation RPC.
- Source, client and explicitly associated patient links preserve existing staff access. A general household message is not guessed into each sibling patient's filter.
- Explicit projections and strict Zod validation exclude message bodies, subjects, raw errors, payloads, protected capabilities, lease tokens and provider configuration. The screen describes message families and opens their existing source for content/review.
- Actor-keyed sessions/queries, editable filter errors, one automatic read retry, retained results on next-page failure and explicit refresh restart.

## Date and paging contract

Activity date means the latest attempt start (canonical), latest lease/start or scheduled time (retained), scheduled date/time (reminder jobs), or creation time before a message's first attempt. Status callbacks do not move a communication to another day. Care jobs have calendar dates without a chosen send hour: Denver midnight represents that date, not a promise to send at midnight.

This is a current-state operations view, not a frozen export or a callback-event ledger. New attempts can move rows across dates or pages. Refresh restarts pagination; read times and loaded counts are labeled. Scheduled reminders require enabled policies and final eligibility; no policy/clinical interval is inferred.
