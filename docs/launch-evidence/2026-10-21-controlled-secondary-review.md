# Controlled secondary-review foundation

This candidate-only package adds an immutable retrospective approve/reject decision
for an already committed controlled-stock event. Gate A, a separately derived v2
metadata reference, and the complete synthetic Auth acceptance passed independent
review. Ordinary, historical and actual CLI compatibility reruns also passed.

The base remains released PR #289, commit
`73b500f7052a9cbd753951216370e1414781f337`. This work does not repeat that release,
install a hosted database change or activate clinical/register workflows.
Final exact-head CI and a READY preview remain required on the new PR, followed
by Dave's approval for that specific merge.

The [machine-readable receipt](2026-10-21-controlled-secondary-review.json) records
source/result digests, counts and scope. Raw executed bytes, catalog observations,
full-row snapshots, failure evidence and attributed cleanup receipts remain in
private evidence; no patient data or session credentials are published here.

Neither profile grants direct application access to private tables or helpers.
Every entry checks both the independent parent and extension seals.

Expectations come from an allowlisted DDL/ACL derivation, cross-checked on a
separate reference realization, then frozen before acceptance. The v2 reference
passed in 51.536 seconds with 284 saved/current inputs, exact source-to-clone rows
and independent cleanup review. It is a metadata reference, not protocol acceptance.

Gate A and v1 expected artifacts remain byte-exact as lineage. V2 contains exactly
two reviewed changes. First, the deferred terminal constraint trigger is a private
SECURITY DEFINER function: deferred execution occurs after the facade's definer

scans at most 100 candidates with a 101st lookahead, rather than 1,000/1,001.
The smaller bound preserves sparse-page continuation and matches the maximum page
size after the larger genuine-writer fixture consumed roughly 12 minutes before
its first signature. Both changes were derived independently; no acceptance
installation was resealed.

## Decision and recovery contract

Supported targets are `receive_inventory`, `adjust_inventory`, and
`record_native_dispense_return_v2:retract_disposal`. A retained, unique controlling
site is required; current container location or policy-site guesses are not
fallbacks. Zero-container annotations are unsupported.

An immutable preparation binds actor, operation UUID, authoritative target tuple,
exact versioned review definition, decision, reason and bounded evidence packet.
It must commit before signing in a different top-level transaction; a savepoint
does not establish that boundary. The 15-minute lifetime is a technical packet
expiry, not a clinical review deadline. The meaning is explicitly independent
record review, with no claim of personal physical observation.

Eligibility uses the live session, active staff account and current application-role
rows in `public.user_roles`. Exact product/site/kind execution and read definitions
are separate immutable version streams. A disabled latest definition has no older
fallback. Self-review remains forbidden across sessions; JWT administrator metadata
does not bypass it. Retrospective review can remain eligible after product
suspension or retirement and does not borrow physical execution permissions.

One event can have one terminal approve/reject decision. Cancellation and execution
serialize through separate review locks; review never takes a physical writer lock
or changes stock. Exact saved-receipt recovery remains available to the same active
actor through a current session, even after execution entitlement or packet expiry,
but never for a changed request or another actor's UUID. Unsaved work rechecks
identity and eligibility after each wait and immediately before persistence.

The queue defaults to 25 and permits at most 100 items, while inspecting at most
100 candidates per call. An empty filtered page can still return continuation.
Cursors bind scope, filters and read-definition version without exposing excluded
event UUIDs. This is a live keyset traversal; earlier status changes require a fresh
traversal. Due time is null and deadline state is `not_configured`.

## Full targeted acceptance

The complete acceptance passed in 1,162.852 seconds within its separately declared
2,100-second workload and 180-second cleanup reserve. Independent review verified
all 287 saved source inputs against executed bytes and current source at that time.

The proof includes 67 real Auth queue RPC checks over 111 genuine targets,
12 observed waits covering three lock stages and four revocation types,
two eligible contenders with exactly one winner, both cancellation/execution
orderings, and 54 schema-negative cases with exact rollback. It exercises
same/nested transaction refusal, account-level self-review, exact retry,
changed/foreign requests, private packet visibility and execution/read separation.

A genuine correction receives its own signature. Its legacy disposal predecessor
is an unsupported unsigned kind; this does not claim transfer of a predecessor
signature. An unrelated saved adjustment receipt remains exact and cannot be
retargeted. Lost-ACK recovery discards the unread application body after HTTP 200
headers; it does not claim loss of transport headers.

The expiry case waited for the actual unchanged 900-second lifetime. PostgreSQL
observed the execute waiter before expiry, then its own clock was past expiry
before and after releasing the blocker. Real authenticated HTTP returned
409/`PT409`, with no terminal append, no packet/receipt exposure for expired work,
and exact recovery of an earlier saved receipt. The authenticated statement timeout
and authenticator statement/lock timeouts remained eight seconds.

## Populated restart and restore

The proof signs one prior preparation after an actual database restart, restores
populated selected schemas into a marked database in the same owned cluster,
retires copied sessions, logs in again through the actual clone Auth service,
recovers exact saved and lost-body receipts, compares the scoped queue, and signs
a different retained preparation through the restored service. Each new signature
is an exact single decision append; original preparations and historical contexts
remain unchanged.

Native owner-preserving dump/restore retains all 212 observed Auth owner/raw ACL
entries, including full untruncated function identities. Both metadata seals, all
457 original row families and review history validate. The clone uses the original
Auth database role. Original service IDs and environments remain exact; only the
declared clone database paths and public-only REST schema exposure differ.

This is selected-schema recovery in an existing cluster. It does not recreate
global roles/memberships, default ACLs or Storage bytes, and does not establish
general extension-member owner/ACL equivalence, GraphQL recovery or physical
events after a backup. Other selected ownership-map differences remain diagnostic.
