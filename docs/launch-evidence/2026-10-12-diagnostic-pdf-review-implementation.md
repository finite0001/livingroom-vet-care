# Internal diagnostic PDF review and download

Patient360 now shows actual PDF preparation/storage/availability status for each reviewed version. Current and historical reports have independent status controls; historical controls load on demand. Downloads remain separate from clinical finalization: no second medical approval was invented. Archived/deceased patients retain readable records. Missing/replaced private objects show unavailable and cannot trigger regeneration or overwrite.

The new CLI-created migration `20261012153518_diagnostic_pdf_staff_review.sql` adds a separate unseeded/off staff disclosure policy, immutable30-second download authorities and immutable `response_prepared` audit rows. Staff projections contain report/version state and byte digest/length, without worker claims, manifests, Storage paths or server keys. Reader identity comes from `auth.uid()`; active profiles and authoritative sorted `user_roles` are locked independently of the original capture/processing actors. Direct table and Storage access stays denied. Internal download does not enable record release or outbound delivery.

The JWT-authenticated `download-diagnostic-pdf` Edge endpoint accepts only request/job/patient UUIDs. Its service-only context resolves the registered private object. A bounded10-second HTTP read verifies MIME, actual length and SHA before final SQL compares exact captured bytes and current object UUID/creation/update timestamps/body generation, reader eligibility, policy binding and authority expiry. A final expiry check follows the potentially blocking unique audit insert; an observed concurrent retry proves expiry cannot be bypassed while waiting. No public or signed URL is returned. Binary responses use private/no-store, PDF content type, sanitized UUID filename and nosniff headers. Audit preparation does not establish user receipt; revocation cannot retract bytes already offered under valid authority.
