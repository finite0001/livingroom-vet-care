# Supplier identity and exact quantity foundation

Current scope: native validation contracts plus reviewed namespace/package APIs, staff review UI and identifier lookup. No supplier file adapter, stock write, camera decoder or controlled register is implemented by this package. The [Phase5 plan](../plans/2026-10-14-inventory-register/plan.md) keeps every required vendor/device/witness acceptance pending.

Supplier identity is `{supplier,namespace_id,sku}`. Supplier is `mwi` or `midwest`; namespace is the practice account/catalog identity and SKU remains original text. Leading zeros and long digit sequences survive. Whitespace/control-character identifiers require review rather than silent normalization. Supplier SKUs are distinct from manufacturer/GTIN identifiers; identical SKU values across suppliers/namespaces do not constitute the same product.

Package conversion is an explicit ratio `{stock_units_numerator,purchase_units_denominator}` of positive integer strings, each at most1000000000000. Purchase quantity is a positive exact decimal string with up to11 whole digits and3 fractional digits. `convertedStockQuantity` uses integer arithmetic and returns canonical three-decimal stock quantity only when the conversion is exact and fits the existing `numeric(14,3)` ledger (maximum99999999999.999). Unsupported fractions/overflow fail; no float coercion or rounding. Clinical units/package/strength and the reviewed version must be supplied by the upcoming package mapping boundary; the ratio alone is not a clinically approved match.

GTIN validation checks the8/12/13/14-digit shape,nonzero value and checksum. A valid code normalizes to14 digits for lookup while the scanner/import must retain the original label/text separately. It does not establish GS1 assignment,product identity,lot/expiry or permission to receive/dispense. Unmatched/ambiguous identifiers will require explicit reviewed mapping.

Code: `src/hub/features/inventory/supplier-imports/{identifier-model,quantity-model}.ts`. Five meaningful unit suites cover exact cases/vials/fractions,rounding/range rejection,malformed/coerced inputs,Supplier leading zeros and GTIN normalization/counterexamples. Full `npm run check` passes1,452 units,lint,typecheck and build. Four preexisting React-refresh warnings and the existing large-chunk warning remain; the dependency lockfile is unchanged. No new Supabase migration or hosted change belongs to this foundation checkpoint.

The reviewed server/UI package adds six private RLS tables and seven authenticated APIs. Only active ADMIN/DVM with a matched live Auth session can publish a version; staff can look up reviewed mappings. Codes bind exact supplier namespace and package versions; namespace retirement or a changed clinical catalog identity suppresses stale lookup. Price-only edits do not invalidate clinical identity. Local recovery stores only actor/action/operation and a request hash, then verifies the original request and exact receipt before clearing it. It survives a reload and never executes during recovery.
