# Inbound worker retry outcomes

`processOneInbound` reports retry/review disposition from `release_communication_event_outcome`, the service-only database RPC added in migration 4300. A transient provider failure can exhaust a cycle and become `review`; the worker no longer infers pending work from its requested error classification. The returned ID must match the claimed event and state must be `pending` or `review`. Missing, malformed or lost acknowledgments fail without asserting either durable outcome.

The old void release RPC remains available for compatibility. Deploy migration 4300 before this worker. This change does not enable provider credentials, change inbound endpoints, send messages, or authorize manual retry. The existing service-side provider retrieval and signed-metadata checks still run after an administrator's reviewed retry.

Focused tests cover pending/review outcomes, tenth-failure exhaustion, malformed/wrong-ID responses, lost acknowledgments, existing fixed provider retrieval, signature checks and capability redaction. The existing localhost inbound acceptance runner is extended for real claim/lease/retry state transitions using only synthetic fixture clock changes. Its provider GET transport is injected; signature, Auth, PostgREST, database ledger and inbox operations are real local operations. No claim of real Resend/Twilio provider acceptance or delivery is made.

Validation: 21 focused inbound tests, scoped ESLint and Deno type checking passed. The local HTTP/Auth/PostgREST runner passed 67 checks against migration 4300, including eight expired leases followed by a tenth transient failure, immutable administrator retry, retained lifetime counts, and a separate ten-expired-lease exhaustion. It also proves the UI's exact `assign_inbound_communication?select=...` projection returns an object with only its 13 requested fields, excludes HTML/attachment metadata, and preserves assignment identity/version. Owned provider-event IDs and committed message children are discovered before fixture cleanup, including the new processing history. Cleanup passed; no external provider requests or sends occurred.

Run with `node --experimental-strip-types tests/inbound/local-roundtrip.ts` against the existing local foundation, or provide `PAYMENT_TEST_PROJECT` for a configured local stack. The runner refuses preexisting pending/claimed inbound work and never starts, stops or resets Supabase. SQL error assertions use the returned SQLSTATE: this PostgREST version maps serialization/expired-lease `40001` to HTTP 500, so HTTP 409 alone is not an accurate lease-conflict assertion.
