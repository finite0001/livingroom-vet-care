This completed closed local experiment connects the reviewed queue reader, read-detail admission and staff preparation workflow against the admitted scalar backend. It is a test fixture, with no production route or default evidence validator.

The input contains a disposable real reviewer session and the fixed product/site/adjustment queue scope. The expected event ID is an assertion only. No policy or eligibility selection IDs enter through input. The user loads the queue, opens its returned row and obtains the five preparation IDs exclusively from the admitted detail. Detail is bound to both the fixed scope and every returned queue-summary field.

The driver permits exactly five POSTs: list, detail, prepare, execute and owned recovery. After list/detail it retains the raw responses and pauses. The parent checks the responses and selection, then compares complete permanent-row hashes before releasing preparation. The route interceptor independently refuses every lifecycle request before that release.

Preparation and acknowledgment are separate actions; acknowledgment sends no request. A later confirmation executes once. The fixture deliberately loses that real successful response. Reload restores only the owned operation pointer, with no queue/detail request or fresh selection. An explicit recovery reads the original operation and removes only its confirmed pointer.
