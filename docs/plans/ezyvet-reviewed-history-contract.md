## Prepared operations

All writes derive the active authenticated actor. Source approval requires ADMIN; extraction and discrepancy review require DVM. Public preparation RPCs take `(p_id uuid,p_pet_id uuid,p_payload jsonb)`; approval takes `(p_id uuid,p_pet_id uuid,p_expected_hash text,p_confirmed boolean)`.

- `prepare_ezyvet_history_approval` / `approve_ezyvet_history`: payload `{animal_link_id,snapshot_id,payload_hash,observed_head_version,patient_version,consult_mode,consult_snapshot_id,consult_payload_hash,consult_head_version,reason}`. Consult mode is `not_referenced|unresolved|verified`; nonverified proof fields are null. Verified context requires exact current scoped same-patient consult observation matching the raw consult reference. A known same-site consult belonging to another animal always rejects approval, including unresolved mode. Missing/zero/empty references are preserved literally, never treated as an invented source convention.
- `prepare_ezyvet_problem_extraction` / `approve_ezyvet_problem_extraction`: payload `{sources:[{id,version_hash}],patient_version,action,problem_id,problem_version,fields:{title,notes,onset_date,status,importance},duplicate_decision,reason}`. Sources are one to20 distinct approved history versions, with at most one version per source history identity in an extraction. Separate extractions can freely share an identity. Action is `create|link`; create has null problem ID/version, duplicate decision `distinct_finding`; link requires exact target/version and exact unchanged target fields, duplicate decision `link_existing`. Title1..250, notes0..10000, onset null or canonical YYYY-MM-DD (never relative date text), status `active|resolved`, importance `routine|high`, all explicitly chosen. Several extractions may share source history. Existing native validators remain authoritative.
- `prepare_ezyvet_history_discrepancy` / `approve_ezyvet_history_discrepancy`: payload `{extraction_id,reviewed_sources:[{original_history_id,reviewed_history_id,version_hash}],reason}`. DVM reviews an ADMIN-approved current scoped version of every original source identity. It changes no local fields. Attention clears only while those exact reviewed source heads remain current; the original extraction is still retained as original evidence.

Shared `recover_ezyvet_history_request(p_id,p_pet_id,p_kind)` returns `{request,receipt}|null`; `abandon_ezyvet_history_request(p_id,p_pet_id,p_kind,p_confirmed)` writes an identity-only tombstone when preparation never arrived. Kind is `history_approval|problem_extraction|discrepancy_review`. Request fields: `{id,actor_id,pet_id,kind,status,request_hash,payload,created_at,resolved_at}`; status `prepared|approved|abandoned`, hash/payload nullable only for identity-only tombstones. Request also includes frozen `review_context`: `{history_source,histories,problem,extraction}` with all keys, empty arrays/null defaults; history approval fills source context, extraction fills approved histories and optional target, discrepancy fills reviewed histories and original extraction. Identity-only tombstones have null context. Exact committed recovery precedes current eligibility, changed reuse fails, and tombstoned IDs never revive. Receipts are the safe history/extraction/discrepancy projections below. Discovery `list_ezyvet_history_requests(p_pet_id,p_kind,p_before_at=null,p_before_id=null,p_limit=20)` returns `{requests:[envelopes],has_more,next_cursor}` for the original actor only. Limits1..50; descending paired `(created_at,id)` cursor, `next_cursor:{before_at,before_id}|null`.

## Clinical projections

`list_patient_imported_histories(p_pet_id,p_before_at=null,p_before_id=null,p_limit=20)` returns `{histories:[history],has_more,next_cursor}` to active clinical staff. `search_patient_problems(p_pet_id,p_search,p_limit=20)` returns bounded same-patient native problem rows. `read_patient_problem_import_provenance(p_pet_id,p_problem_ids uuid[])` returns `[{problem_id,extractions:[extraction]}]`, at most50 problem IDs. No raw staging access is granted to DVMs.

History fields: `{id,version,version_hash,pet_id,animal_link_id,source:{origin,site_uid,animal_id,history_id},snapshot_id,payload_hash,observed_head_version,original:{comments,history_system,chain,timestamp,vet_id,active,consult_id},approved_by,approved_at,consult,current}`. Original values preserve JSON/null and must be rendered escaped literally, never interpreted as dates or local staff. Consult is `{status}` with `snapshot_id,payload_hash,observed_head_version,external_id` only when verified. Current is `{snapshot_id,head_version,scoped,is_current,source_active}`. Current head IDs/revisions are nonnull; activity is preserved JSON/null. `is_current` requires exact approved snapshot AND head revision, scoped observation, valid patient/source mapping and unchanged verified consult context. Thus false is possible even when the history snapshot/revision still matches. A→B→A does not revive old approval.

Extraction fields: `{id,problem_id,action,problem_version,problem_fields:{title,notes,onset_date,status,importance},extracted_by,extracted_at,sources,current_problem_version,locally_edited,discrepancy}`. Sources are compact history references, not automatic disclosure of all original prose. `locally_edited` is current problem version differing from the immutable extraction target version. Discrepancy is `{required,reviewed,changed_from_original,review_history:[review]}`. Each review has `{id,reviewed_by,reviewed_at,source_heads:[{history_id,snapshot_id,head_version}],sources:[compact_history_ref]}`. Private reason and duplicate-decision prose are excluded from clinical exports.

Compact history reference: `{id,version,version_hash,source,snapshot_id,payload_hash,observed_head_version,approved_by,approved_at}`. Source has the same four origin/site/animal/history fields. Clinical staff may open the approved narrative separately.
