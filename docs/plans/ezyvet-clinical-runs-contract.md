# Patient-scoped clinical ingestion contract —4900

Consult/history imports preserve outside observations. No native chart, signature, diagnosis, prescription, stock or billing entry is created. No live source access or commissioning is implied.

Service RPC `claim_ezyvet_clinical_import(p_id uuid,p_actor uuid,p_site_uid text,p_resource text,p_source_origin text,p_animal_link_id uuid)` accepts only consult/history and returns existing import-run JSON plus `animal_link_id,animal_external_id,pet_id,client_id`. The run UUID permanently belongs to its original actor, mapping, site, origin and resource. Existing UUIDs without clinical context cannot be rebound, even terminal runs: SQL22023 with exact message `CLINICAL_RUN_REQUIRES_NEW_MAPPING`. Generic consult/history claims fail23514. Existing leases and source/resource cooldowns remain effective.

Existing service `stage_ezyvet_import_page(p_id,p_actor,p_lease_id,p_page,p_complete,p_items)` remains the staging entrypoint. Clinical pages require at most10 objects, exact numeric source IDs, payload.id matching external_id and payload.animal_id matching the frozen mapping. Other source references/text remain opaque. The immutable receipt hash covers p_complete and the original ordered JSONB items. Processing sorts clinical items by external_id before acquiring source head locks; that canonical processing order does not weaken exact ordered retry identity. Exact committed replay recovers before current patient eligibility/lease checks, still requiring the active original actor and original context. Changed replay fails40001. Legacy late pages fail22023 before cursor or source head changes. Each validated page item captures its observed head version atomically under the source head locks retained by staging.

## Shared staging correction and local evidence

The4900 wrapper also closes an inherited SQL NULL lease comparison gap for generic and healthstatus fresh pages. Missing, cleared, expired or null caller leases cannot authorize a new page. Existing committed nonclinical page recovery remains compatible after the active owner check, including cleared leases; clinical recovery additionally compares its immutable page fingerprint. The original private core stays inaccessible to API roles.

Local validation:59 focused SQL assertions,156 existing import/review/weight/release-weight assertions, and41 observed-lock contention checks. The concurrency runner uses a verified local container and an owned schema-only disposable database; it verifies the exact ownership marker before removal and confirms removal. Reversed overlapping pages and simultaneous valid leases are explicit owner-only adversarial fixtures. A privileged patient membership change is simulated only in that isolated database; today's native patient API forbids ownership transfer. No clinical policy is activated, no foundation patient data is retained and no provider request is made.

Candidate `created_at` is the snapshot's first storage time, not the latest scoped observation time or an outside clinical timestamp. Current scoped freshness is carried by `observed_head_version`, never inferred from that timestamp. Later native import approval must compare the source hash AND current observed head revision independently.
