# Audited outgoing-message recovery

Baseline c1a3f5b. Status: implemented and locally verified in the outbox retry acceptance integration. Implementation increment: safe pre-provider retry review; full provider reconciliation remains an explicit commercial commissioning requirement.

The existing retry_communication(actor,id) has no stable action UUID or expected work hash. Repeating it after a lost acknowledgment can act on a later failure. No staff browser consumes it. Operations currently discovers failed/uncertain items but cannot authorize a recoverable retry.

Add migration4500 with ADMIN-reviewed preview, exact UUID/hash/reason/attestation action, immutable receipt, actor-scoped recovery/history and bounded safe projection. Initial eligibility is failed work with no provider_message_id, no attempt timestamps/count/rows and no prior delivery/provider evidence. Require current original actor, recipient and consent. Preserve immutable source/payload/sender context and every existing final preflight wrapper. Do not invoke mutating worker functions from preview. Source-specific ineligibility must remain blocked; if a final condition cannot be evaluated without materialization, describe requeue eligibility distinctly from delivery eligibility.

Lock outbox before state/hash check and action; include immutable intent digest, exact failure state/version, attempt/evidence facts and source context in the reviewed hash. A row revision must change on actual outbox changes so identical clock timestamps cannot hide a later failure. The stable action UUID binds actor, outbox, hash, reason and attestation. Exact receipt recovery precedes current eligibility; mismatched replay rejects. One action atomically records its receipt/audit and returns the same outbox to pending without new payload. Revoke the old unversioned public retry path; retain private implementation only if the reviewed wrapper is its sole authorized caller. No provider requests or automatic retries.

ADMIN UI: link exact outbox from Operations, display safe original context and explicit repair attestation; save original request before submission, recover before retry, prevent changing target while uncertain, recover own history after browser-pointer loss, preserve draft/account boundaries. Read-only operations remains read-only. Never label queued/retried as sent. Unknown/missing receipts retain the original request. Cleanup requires strictly increased outbox revision versus the separately persisted reviewed revision and a second missing receipt; a reversible external-source hash change is insufficient.

Acceptance: late first response followed by a second worker preflight failure; competing reviewers; changed request fields; current contact/consent/staff changes; expired/invalidated clinical/reminder/document/payment source guards; rejection of uncertain, previously attempted and accepted work; exact original payload/attachments unchanged; private/RLS projections; actual local Auth/PostgREST plus browser review/reload/history. Add meaningful contention and actual HTTP checks to CI. No hosted writes while migration coordination is pending.

Remaining provider recovery: uncertain SMS, Resend requests after possible provider execution or account changes, accepted messages and expired idempotency windows require independently verified provider identity/status/non-acceptance. Existing service-only reconciliation requires an operator evidence reference. This increment does not invent non-acceptance, supply API credentials or claim those cases commercially accepted. Provider-account commissioning and controlled acceptance must resolve that remaining requirement.
