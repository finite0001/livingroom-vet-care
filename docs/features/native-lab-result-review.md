# Native lab report provenance and review

Staff can associate uploaded original reports with a saved patient lab order while preserving its notes, due plans, status, existing `result_document_id`, and native correction history. This is a manual workflow. It does not configure Antech transport, interpret a report, or send it to a client.

An ADMIN records nonsecret source account/environment identifiers. Staff explicitly review the source account, patient reference and order reference against a saved order version. Revisions retain prior mappings. A selected ready same-patient PDF/JPEG/PNG report (1 byte through 20 MiB) is staged through `prepare-lab-report`; the service reads the private file and calculates its digest. No digest can be supplied by the browser.

The panel displays staged source references, received time, exact document version, media type and byte count. Staff download the original through authenticated private storage; the browser compares the downloaded bytes with the service capture before enabling an attested link. Linking freezes the current mapping, order version, receipt hash, capture hash and prior report. A mismatch stays staged. A corrected report is linked as a new report version with an explicit correction reason and prior report identity; it cannot overwrite original evidence.

DVM users separately download and acknowledge each exact clinical report version. ADMIN alone does not confer that permission. An earlier acknowledgment does not cover a corrected report. Historical reports and acknowledgments remain visible when a document becomes unavailable, while new linking or acknowledgment remains disabled.

Every mutation saves one stable UUID and its exact reviewed arguments before submission. Lost replies first recover actor-owned receipt metadata or discover the corresponding saved action in history. A retry uses the original arguments; a definite missing action can be explicitly discarded only after a second absence check. An incomplete staged receipt can also be resumed by its original actor after session cleanup, using its original UUID, source references and exact timestamp. Other actors can inspect it but cannot resume its verification. A captured receipt remains available in patient history after its local request is cleared. Source-reference and review drafts block native lab edits and patient navigation through the existing parent dirty guard; native edits block new provenance actions. Signout and account changes remove `lab-result-intent:` session records. Document bytes and object URLs are memory-only and revoked on page exit.

Dependencies: migration 4100 and the default-off `prepare-lab-report` verification endpoint. Missing configuration shows an unavailable/unconfirmed action and preserves recovery; it never implies a connected laboratory. No provider or clinical interpretation API is called.

Validation uses synthetic local fixtures: cross-patient/actor/capture rejection, timestamp precision and exact retry intent, correction acknowledgment binding, session cleanup, lost verification/link replies, stale mapping recovery, parent dirty guards, DVM/ADMIN separation, and unchanged native lab fields. Browser tests mock transport and private document bytes; SQL and Edge authorization/integrity checks are validated independently by their backend suites.
