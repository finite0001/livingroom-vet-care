# Native handoff and correction source boundary

Status: locally verified; exact-head CI and staged rollout pending; hosted backends remain at 188. This C1b prerequisite extends [PR256’s eight-writer boundary](stock-writer-boundary.md) to ten producers. It is separate from the unfinished [controlled-stock execution protocol](../../plans/2026-10-14-inventory-register/controlled-stock-context-design.md).

`record_native_pickup` and `append_native_dispense_correction` now enter the existing shared transaction barrier before their old locks. The migration verifies both complete prior definition hashes and all eight existing manifest entries. It adds only the first entry call to each body. Original signatures, request fingerprints, accepted mixed-case pickup UUIDs, server timestamps, role requirements, committed receipts and API grants remain intact; the new entry also requires READ COMMITTED, as the other eight writers do.

Two private RLS relations, `stock_pickup_sources` and `stock_correction_sources`, link each new native event to its actual recorder and original root UUID. Neither clients nor service workers can read or write these relations or call their two private trigger helpers. Immutable guards reject rewriting, deletion and truncation.

Before/after insert guards require the exact admitted writer, root and actor. Deferred checks run from both native events, both reverse-source tables and both operation-receipt tables. They bind the original event, actor, patient/authorization/dispense identity, saved document, exact request hash and relevant handoff/correction fields. Correction document hashes are recomputed. An orphan event, source or pickup receipt cannot commit. An earlier legitimate call in the same PostgreSQL query packet cannot authorize another root.

Pickup and correction evidence do not debit or refund inventory, add charges or rewrite the original handoff. In particular, marking a pickup “recorded in error” disputes the assertion; it does not establish that the medication physically returned. A later controlled workflow must handle that investigation explicitly.

Existing handoffs are not backfilled. Exact old receipts remain recoverable without invented provenance. A populated upgrade rehearsal reconstructs the two exact prior bodies, retains original clinical/financial history, rejects source drift atomically, applies the new boundary and checks legacy recovery plus a new correction. Populated restore covers the additional source families and exact original pickup/correction receipts.

Local verification includes the canonical SQL suites, real Auth/native/browser regression, all ten observed early barriers, source/privacy denials and populated restore. The [12-check rollback-only probe](../../scripts/stock-writers/handoff-rollback-probe.sql) exercises a canonical dispense, pickup, disputed-pickup amendment and exact retries in one query packet. It verifies one stock debit, one charge and preserved original handoff; all fixtures roll back. The existing [22-check stock probe](../../scripts/stock-writers/rollback-probe.sql) remains required.
