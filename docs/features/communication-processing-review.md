# Communication processing review

The inbox links to `/hub/inbox/processing`. Active staff read the safe migration-4300 processing projection, with state filters and bounded received-time/ID pagination. It shows the provider, callback type, processing state, safe failure category, cycle allowance and preserved lifetime attempts. Provider IDs are available as operator references. Raw callback metadata, HTML, lease tokens and upstream error text are never requested or displayed. A processed callback is not itself a claim that an outgoing message was delivered.

An active ADMIN may open the exact retry preview. The UI displays recorded history and the limited `legacy_snapshot` evidence as such. Content, crash-only, unknown and unexhausted failures remain ineligible. An eligible exhausted generic fetch/persistence failure requires a completed repair reason and explicit attestation before requesting one new processing cycle. The database remains authoritative for work-hash equality, eligibility and concurrency.

The original retry UUID, event ID, work hash, reason and attestation are stored before submission. A lost acknowledgment recovers the original action receipt before consulting eligibility or attempting another mutation. Exact retry never creates a fresh UUID. Receipt proof distinguishes a recorded cycle from subsequent processing or delivery. An administrator can also recover their recorded actions from paginated history after losing the browser pointer. A missing action can be discarded only after a second exact recovery read confirms absence.

A recorded retry preserves provider receipt facts, lifetime attempts, suppression/consent restrictions and delivery evidence. It makes no provider request. A worker must still fetch, validate and process the content through its ordinary guarded path. Household assignment remains a separate unmatched-message review.

The page guards navigation while reviewing or holding a pending request. `communication-processing-intent:` is scoped to the signed-in actor, removed by auth cleanup, and never read or submitted by the staff-only queue view. No sending flags, credentials, hosted state or provider configuration are changed.

Synthetic tests cover safe projection parsing, ineligible content/crash work, first cycle 0→1 without resetting lifetime attempts, exact actor/hash/UUID/reason receipts, lost acknowledgments, unchanged retry after reload, pointer-free history recovery, role boundaries, stale work and signout cleanup. Backend SQL/concurrency/HTTP tests validate actual authority and worker outcomes independently.
