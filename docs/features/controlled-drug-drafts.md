# Controlled-drug draft configuration

C0 proposes medication configuration for review. It is not a running drug register. Every stored entry has the database-constrained state `draft`; no opening, physical event, witness, waste, count or activation endpoint is introduced. No drug classification, registration or physical quantity is seeded.

Active ADMIN/DVM staff with a matched live Auth session may prepare and publish a metadata revision. STAFF may read bounded draft lists/history and recover their own historical reviews where applicable. Raw tables and private helpers are unavailable to anonymous, authenticated and service-role callers. A worker key cannot substitute for a staff session. Definitions contain exact catalog medication/version/unit, proposed Schedule II–V, generic/optional brand name, concentration text with its source, classification source and a configuration note. The UI requires an explicit schedule choice. Concentration text performs no dose or quantity conversion.

One medication has one stable draft identity. Versions, prepared requests, original receipts and cancellation tombstones are immutable. A revised catalog requires an explicit fresh review; an already committed original receipt remains recoverable. Product-wide serialization prevents different draft IDs from claiming one medication. Deferred constraints verify exact head/version/request/action/receipt evidence. Unicode edge trimming and single-line/multiline text rules agree with the browser.

Before transport, the browser stores only the original actor/action/operation and request fingerprint. It retains those recovery details after an uncertain response or reload. Checking saved work is read-only; an intentional retry preserves the original UUID and exact request. Cancellation serializes with execute and cannot erase a committed revision. Actor changes cannot adopt another user's review. Pending/dirty work has explicit departure confirmation.
