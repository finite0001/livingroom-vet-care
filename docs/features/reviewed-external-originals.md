# Reviewed external originals in the patient chart

The patient chart separates staff-reviewed manual ezyVet exports from native clinical data. Preserving an original does not convert SOAP notes, diagnoses, vaccine administrations, lab observations or billing, and does not claim an active provider connection.

An active ADMIN selects an already-approved ezyVet animal mapping for this patient, an existing ready private `medical_record` document, a source export reference, and a review reason. The source origin/site/animal identity is displayed explicitly. Original verification freezes the mapping, current patient version, document version, received timestamp, export reference, prior record and reason before calling `prepare-external-record`. The service verifies PDF/JPEG/PNG bytes (1 byte through 20 MiB); callers never provide a digest.

After verification, the administrator downloads the original. The browser independently compares its bytes with the service capture before enabling the explicit chart approval. Approval preserves an append-only original or replacement. A replacement starts from a history entry, retains its mapping and export reference, requires a new document, and is checked against the current series head by the database. Review is distinct from clinical acknowledgment.

Active staff can read paginated original/replacement history, including source provenance and unavailable-document history. Only DVM users can download and acknowledge an exact clinical original; ADMIN alone does not confer that role. A replacement retains earlier acknowledgments in history but is not acknowledged by them. Actor-owned DVM acknowledgment recovery works independently of the currently visible history page.

Each pending operation stores its original UUID and exact reviewed arguments under `external-record-intent:` before network submission. Verification and approval recover from actor-owned receipt metadata before any retry. Incomplete server receipts can be resumed after session storage is cleared, preserving their original UUID and authoritative received timestamp, including database microseconds. A timestamp is never rounded to claim an unchanged intent. Confirmed absent actions can be explicitly discarded only after a second read. No server evidence is deleted.

Document bytes and generated object URLs remain in memory and are revoked on page exit. Account changes and signout clear local pending intents and invalidate late responses. The panel contributes to the shared patient navigation guard and blocks new external-record actions while another clinical draft is active. It preserves native patient fields and the existing lab provenance workflow.

Dependencies are migration 4200 and the default-off external-record verification function. No provider credentials, transport, clinical interpretation or client release is added. Synthetic tests cover exact receipt recovery, lost preparation/approval acknowledgments, later-page DVM recovery, patient-version rejection, source/document/capture validation and session cleanup. Backend suites independently validate SQL roles, source identity, byte integrity and concurrent replacements.
